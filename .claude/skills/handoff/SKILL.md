# 引き継ぎ(handoff)

会話履歴は記憶装置ではない。**次のセッションが読むのはファイルだけである。**
このスキルは「会話にしか無い情報」をゼロにしてからセッションを切るための手順である。

根拠と閾値は `Documents/10_CONTEXT_POLICY.md` §2.4。形式は `AGENTS.md` §受け渡しプロトコル。

---

## 1. まず、いま切るべきかを判定する

以下のどれか1つでも当てはまれば切る。**迷ったら切る**(`/clear` はコストがゼロ)。

| 徴候 | 根拠 |
|---|---|
| hook `context-guard` が警告を出した(約10万トークン超) | 実測値。10_CONTEXT_POLICY §2.4 |
| PLAN を1本終えた | 1セッション = 1 PLAN |
| 話題が PLAN の範囲外に移った | 無関係な文脈が以降の全リクエストに乗り続ける |
| 同じ問題で2回訂正しても直らない | §2.2 撤退基準。コンテキストが失敗試行で汚れている |
| 大きな出力(テストログ・実験ログ)を3回以上コンテキストに流した | 以降の判断が引きずられる |

当てはまらなければ、ここで止めて作業を続けてよい。**手順2以降を空回しさせない。**

---

## 2. STATE.md を更新する

`STATE.md` の以下を、いまの事実に合わせる。書式は既存の節をそのまま踏襲する。

- 冒頭の「最終更新 / 現在のフェーズ」
- 「いま何をしているか」
- 「わかっていること」— **数値は run_id とセットでのみ書く**(`CLAUDE.md` §2)
- 「わかっていないこと」
- 「次のアクション」
- 「引き継ぎ」ブロック(完了したこと / 次にやるべきこと / 未解決点)

---

## 3. logs/HANDOFF.md に次セッション用プロンプトを書く

**上書きする。**履歴は git が持つ。以下の型を埋める。ここに書いたものが
次のセッションの最初のコンテキストになるので、**短く、具体的に、検証可能に**書く。

```markdown
# HANDOFF — 次のセッションに貼るプロンプト

生成: YYYY-MM-DD / 直前セッションの役割: <PLANNER|IMPLEMENTER|RUNNER|ANALYST|CRITIC>
直前セッションが終了した理由: <コンテキスト超過|PLAN完了|撤退基準|話題変更>

---

あなたは <役割> です。`CLAUDE.md` §1 の開始手順を実行してから作業を始めてください。

## このセッションでやること(1つだけ)

<具体的な成果物。「〜を調査して」ではなく「〜を code/eval/parsers/numeric.py に実装し、
code/tests/ にテストを追加して pytest を通す」のように、完了条件が判定できる形で書く>

## 直前セッションで確定したこと

- <ファイルに書き込み済みの結論だけ。会話でしか触れていない話は書かない>
- <数値は run_id とセットで。単独の数値は書かない>

## 触ってよいファイル / 読むべき範囲

- <パス:行範囲>。全文 cat せず `grep -n` → `sed -n 'X,Yp'` で読むこと

## やってはいけないこと

- <直前セッションで踏んだ地雷。失敗した実装案とその理由を1行で>

## 未解決 / 人間の承認待ち

- <`CLAUDE.md` §8 に該当するもの。エージェントが独断で決めてはいけない>
```

**書かないもの**: 探索の過程、失敗した試行の全文、ツール出力の生データ、
既に `STATE.md` や設計文書に書いてある内容の再掲。

---

## 4. 記録して閉じる

```bash
# logs/CHANGELOG.md に追記してから
git add -A && git commit -m "docs(plan): セッション引き継ぎを記録"
git status   # 未コミットが残っていないこと
```

RunPod を使ったセッションなら、**ポッドを停止したかをここで必ず確認する**(`CLAUDE.md` §9)。

---

## 5. ユーザーに伝える

最後に、次の3点だけを短く出す。長い要約を会話に流さない(それ自体がトークンである)。

1. **なぜ切るのか**(判定した徴候と、実測のコンテキスト量)
2. **`/clear` してください**(`/compact` ではない。区切りが明確なので `/clear` が安い)
3. **`logs/HANDOFF.md` の中身をコピーして新しいセッションに貼ってください**
   — そのまま貼れる形で、コードブロックとして会話にも1回だけ出す

ユーザーが `/clear` するまでは新しい作業を始めない。
