## 2. その72〜75 の実質的な問題(重い順)

### B1. ★`dgp.n_item` は `M*` ではない(**次のセッションが実行すると壊れる**)

- `STATE.md`「次のアクション」2 が **「`dgp.n_item` に `M*` = 999(ADR-074)を反映する」**と指示している。
  同じ読みが ADR-094「この決定が決めていないもの」、`Documents/05_STATISTICS.md` §6.7 脚注、
  `plans/PLAN-019` §10.13.5 末尾、`code/analysis/power_sim.py` の docstring にある
- **事実**: `n_item` は **(タスク型 × 被覆水準)のセルあたりの項目数**である(`code/analysis/power_sim.py:233` の
  `for k in range(levels.n_item)`、`configs/power_sim.yaml` のコメント「被覆水準あたりの項目数」)。
  `Documents/05_STATISTICS.md` §6.4 は「**`n_item` は `eval.pool_items`(B5)に依存し、これが `M*` 待ちだった**」と書く。
  **`M*`(桁数格子の上端 999)を `n_item` に入れるのは単位の取り違えである**
- 経緯: その70(Opus)の文は「`dgp.n_item` の待ちだった `M*` は 999 に決まった(値の反映は未実施)」で、
  曖昧だが「n_item を 999 にする」とは言っていない。**その75 がそれを指示文に書き換えた**
- 害: 本実行のコストは `n_item` に比例する(62 時間は `n_item = 48` での実測。run `20260909_bench_powersim`)。
  999 を入れると約 21 倍になり、しかも本番のプールと関係のない検出力を出す
- **対応(案)**: `n_item` の正しい値は本番プールのセル表(ADR-076 決定10 の `fill_cells`)から数えて人間が確かめる。
  **本監査で `STATE.md` の指示文は直した**(§6)。ADR-094 等の文言の訂正は人間の確認後

### B4. ★F104-c の値は、エージェントが提案しない約束だったものを Sonnet が推奨した

- `plans/PLAN-019` §10.13.5(その28。Opus)は **F104-a で「エージェントは B / C のどちらも推していない」**、
  **F104-c で「★エージェントは値を提案しない。人間が凍結する仮定である(ADR-053 決定2 と同じ立場)」**と書いていた
- その74(Sonnet)は F104-a に案 C を推奨し、値に「中庸」として `s2_item ≈ 1.0` を例示した(`1495ab4` の HANDOFF)。
  その75(Sonnet)は 3 択に推奨を付けて `AskUserQuestion` に掛け、人間が推奨を選んだ
- 同じ表の中で「エージェントの案 = 値を提案しない」と「決定 = エージェントの推奨どおり」が並んでいる(自己矛盾)

### B5. ADR-093 P3(前段プールの非交差)は定義が曖昧で、根拠が当てはまらない可能性がある

- ADR-093 P3 は「前段プールの**値域**は主実験訓練域 `[1,99]^2` と非交差」。PLAN-028 §3.3・§6 は
  「訓練域**・評価域**と非交差」と書いており、**2 つの文書で範囲が違う**
- 既知性ラベル(`id` / `interp` / `extrap_*`)は**加算の被演算子の組** `(a, b)` が病変 FT の訓練集合に入ったかで決まる。
  ③-ii の `x>y?` は加算の組ではないので、「前段で見た組は後段にとって見たことがある組になる」という根拠は
  **そのままでは当てはまらない**。T3 の項目が実際に比べているのは `(a+b, t)` である
- 「値域」を「数が 1〜99 に入らない」と読むと、**2 桁どうしの比較を前段で一度も訓練しない**ことになる。
  T3 の `id` / `interp` で和が 100 未満の項目は、まさにその比較である
- **PLAN-029 I1・I3 の実装より前に、人間が P3 の意味(組か値か / 訓練域だけか評価域もか / 何を守るための制約か)を決め直す必要がある**
