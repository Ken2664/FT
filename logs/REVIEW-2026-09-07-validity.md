## 0. 総評

**この研究の設計上の弱点は「杜撰さ」ではなく「一貫性の適用漏れ」である。**

repo は査読で最も問題になる 2 種類の失敗 —— **HARKing** と **チェリーピッキング** ——
に対して、私が見た範囲では標準を超えた防御を持っている。具体的には:

- **主要評価項目が 1 つに絞られ、その弱点が実験前に本文に書かれている**(§2 の 4 項目)
- **旧記述を打ち消し線で残し、差し替えの日付と「実験は 1 件も実行していない」を毎回添えている**
- **提案者と採択者を ADR で分けている**(ADR-039 決定3)
- **「有意差がなかった」を TOST に落とす規約が本文にある**(§5)
- **最も退屈な対立仮説を各所で先に書いている**(適格性フィルタ / PLAN-017 §8)

**問題は、この厳格さが主要検定そのものには一様に掛かっていないことである。**
以下の ★G 〜 ★J は、いずれも **repo が別の箇所で既に受け入れている論法を、主軸に適用すると出てくる**。

**★K は性質が違う。**これは設計変更の提案であり、重い。**窓はいましか無い**(プールを作り直す必要がある)。

## 1. 統計的結論の妥当性

### ★G(新規・最重要): 主要検定のランダム構造が、宣言した反復単位を守っていない

**事実**:

- `Documents/05_STATISTICS.md` **§3.1 は「反復単位は 1 回の FT run(= 1 シード)」を最重要と宣言している**
- **§3.2 の主軸のモデルは `(1 | seed)` の切片だけである。**`coverage` にも `task` にも
  シードのランダム傾きが無い
- したがってモデルは **「`task:coverage` の交互作用は 40 本の FT run を通じて一定である」** と仮定する

**なぜ問題か**:

- 交互作用が run 間で変動するなら、その変動は項目内誤差に畳まれる。
  **固定効果 `task:coverage` の SE が過小になり、df = 6 の LRT は反保守的になる**
- **repo はこの論法を既に受け入れている。**§3.2 の 順1b の欄(:193-196)は
  「切片だけの指定は『`id` → `interp` の落差が run 間で一定』と仮定する。**偽なら DiD 交互作用の
  SE が過小になり、検定は反保守的になる**」と書き、**S5 として人間に上げている。**
  **同じ文がそのまま主軸に当てはまるのに、主軸には上がっていない**
- **さらに悪いことに、研究仮説 `H2` の第2節は「破れの位置がシード間で一貫しない」と予測している**
  (`Documents/01_HYPOTHESES.md`)。**予測している当のものを、主軸のモデルは誤差に畳んでいる**

**選択肢(人間が決める)**:

| 案 | 中身 | 代償 |
|---|---|---|
| (a) | **S5 を主軸にも開く。**`(0 + coverage \| seed)` を足す | 収束が厳しくなる。ADR-059 の縮退順序に載せる必要がある |
| (b) | **`(0 + task \| seed)` を足す** | 4 水準。交互作用の run 間変動のうち task 側だけを吸う |
| (c) | **2 段階に分ける。**run ごとに交互作用の 6 成分を推定し、その run 間分散で検定する | 最も反復単位に忠実だが、10 点での推定になる |
| (d) | **切片のまま凍結し、Limitations に「run 間で一定を仮定した」と明記する** | 最小。**ただし §3.1 の宣言と矛盾する** |

**★どれを採っても、順1b の S5 と同じ場で決めるのが筋である**(同じ問題だから)。

### ★H(新規): 「勾配が平行」はリンク関数に依存する結論である

**事実**:

- 主要検定は二項 GLMM の **ロジット尺度**での加法性の検定である。
  「平行」は**尺度の性質**であって、データの性質ではない
- **Go/No-Go #4 は基準セル(`T1 × id`)の `rule_rate` を ≥ 0.90 に押し上げる設計である**
  (`Documents/04_EXPERIMENT_PLAN.md`)。**基準セルは天井付近に置かれる**
- repo はこの弱点を **2 か所で認識している**: §3.2 の 順1b(:190-191「**`p2` の `id` が天井に
  貼り付くと `p2` 側の差が圧縮される**」)と、§3.2 のベイズ事前分布の根拠(:150
  「基準セルは天井に近い設計であり」)
- **しかし §2 の「この主要検定の弱点(実験前に書いておく)」の 4 項目には入っていない**

**なぜ問題か**: 天井付近ではロジットが伸びるので、`id` セルの小さな率差が大きなロジット差になる。
**タスク型ごとに天井への近さが違えば、それだけで「勾配が平行でない」が出る。**
probit や恒等(リスク差)尺度では結論が反転しうる。

**選択肢**: **リンク関数を変えた感度解析を事前登録する**(probit / cloglog、あるいは
リスク差での非加法性)。**3 本とも同じ向きなら頑健、割れたら尺度依存であると報告する。**
**追加 GPU は 0 である**(同じ長形式表に当て直すだけ)。

### ★I(新規): 適格性フィルタでセルが落ちたときの df が事前登録に無い

**事実**:

- `plans/PLAN-003-redesign.md` §6.3 の適格性フィルタは、**`ident` の `correct_rate` が 0.70 未満の
  (タスク型 × 既知性)セルを主解析から除外する**
- §2 は「**フィルタでセルが落ちた場合、結論は『解ける範囲では』に限定される**」とだけ書く
- **`df = 6` は 4 × 3 の完全格子を前提とする値である。**セルが 1 つ落ちれば
  `task * coverage` の設計行列が変わり、**事前登録した df = 6 の検定は存在しなくなる**
- **最も落ちやすいのは `T2 × extrap_magnitude` である**(`150 + 150` の文章題)。
  これは §2 自身が「最も退屈な対立仮説」として名指ししているセルでもある

**repo には良い前例がある**: ADR-047 決定2 は、T1b が Go/No-Go #3 を割った場合に
**「df 6 → 4 に落とす」ことをトリガーごと事前指定している。** **セル落ちにも同じ形が要る。**

**選択肢**: 落ちうるセルの組み合わせごとに **df を事前に表で固定する** /
または **「セルが落ちたら該当タスク型ごと落とし、3 タスク型 df = 4 で検定する」**と決める /
または **フィルタを主解析から外し、共変量版(§6.3 の感度解析)を主解析にする。**

### ★J(新規): 従属変数の測定モデルがタスク型間で違い、その非対称が主要交互作用を直接作りうる

**事実**:

- **T1b / T3 は強制選択採点である**(ADR-047)。`parse_fail` と `other_error` は**構造上 0** で、
  `correct + rule = 1` に潰れる
- **T1 / T2 は自由生成である。**`parse_fail` と `other_error` が正の質量を持つ
- **`rule_rate` の分母は全項目である**(`code/rates.py`。4 値の合計は 1.0)。
  すなわち **`is_rule` は `parse_fail` を 0 として数える**(`code/analysis/frame.py` の `is_rule`)
- したがって **数値タスクだけが「真値でも規則値でもない」質量を失う。**
  そして**その損失は既知性が上がるほど増えると見込まれる**(`150 + 150` の文章題で崩れる)

**なぜ問題か**: これは **出力型 × 既知性の交互作用そのもの**である。
**ADR-052 決定2 が採択した効果量プロファイル P2(出力型で割れる)と同型の人工物である。**
すなわち **主要検定が拾いうる形の 1 つを、測定方式が最初から作っている。**

**設計上の歯止めはある**(公平に書く):

- Go/No-Go **#1**: `parse_fail_rate < 0.02`(T1 / T2、`none` モデル)
- Go/No-Go **#5**: `other_error_rate < 0.10`(全セル、`p2` パイロット)
- §2: 「**`other_error_rate` が主導しているセルは交互作用の解釈に使わない**」

**しかし歯止めの大きさが、検出したい効果量と同じ桁である。**
合計 ~0.12 の率差は、`p ≈ 0.5` 付近で **約 0.4 ロジット**にあたる。
**ADR-052 決定2 が採択した検出下限は非加法性 RMS = 0.353 ロジットである。**
**歯止めの内側に、検出したい効果と同じ大きさの人工物が入る余地が残っている。**

**`Documents/06_THREATS.md` T14 はこの非対称を書いているが、向きが違う。**
T14 は「**崩壊の検出**が数値タスク側に移譲される」と書く。
**「非対称が主要交互作用を作る」向きは書いていない。**

**選択肢(安い)**: **主要 LRT を `rule / (correct + rule)` に再正規化した DV でも当てる感度解析**を
事前登録する。**追加 GPU は 0。**
**ただし処置後変数での条件付けになるので主解析にはできない** —— 併記に留める。
**あるいは #1 / #5 の閾値を、検出下限から逆算して締め直す。**

## 2. 設計の妥当性(重い提案。窓はいましか無い)

### ★K(新規): 主軸は全面的に項目間(between-item)計画であり、§3.2 の記述と食い違う

**事実**:

- `code/data_gen/pool.py` の `fill_cells` は **セル間で組を再利用しない**(`used` はグローバル。
  :621 に「**同じ組を2つのセルに入れない。項目が重複すると項目ランダム効果が壊れる**」と明記)
- `code/data_gen/battery_items.py:121` の `item_id` は
  **`pool_id.group.category.operands...`** である。**タスク型が違えば別の水準になる**
- `plans/PLAN-001-eval-battery.md` の `id` 要求は **520 組**であり、これはタスク型ごとの
  `id` セルの項目数の**総和**である。**すなわちタスク型間で組は共有されない**
- 割り当ては**シード固定のシャッフル後**に先頭から取る(pool.py:629-630)。
  **偏りは無い。バイアスの問題ではない**

**食い違い**: **`Documents/05_STATISTICS.md` §3.2 は `(1 | item)` を
「被演算子対のランダム切片」と説明している。**実装では対ではなく
**(群 × category × 対)**である。**同じ `(50, 50)` が T1 と T2 に現れることは無い。**

**なぜ問題か(検出力の問題であって妥当性の問題ではない)**:

- **12 個の互いに素な組の集合を比べている。**対の難度はすべて残差に乗る
- **同じ組を 4 タスク型で共有すれば、`(1 | item)` が真に交差し、対の難度が `task` 対比から
  完全に落ちる。**これは §3.2 の記述が想定している設計そのものである
- **副産物として `id` 要求(520 組)が下がる。**PLAN-001 §5.1 が「`K = 500` では埋まらない」と
  書いた制約が緩む
- **pool.py:621 の反対理由(「項目が重複すると項目ランダム効果が壊れる」)は、交差ランダム効果
  については成立しない。**交差は重複を前提とする設計である。
  **壊れるのは「同じ項目を同じ解析の中で 2 度数える」場合であって、
  別のタスク型で同じ対を使うことではない**

**代償(正直に書く)**:

- **プールを作り直す必要がある。**`eval.cells` は未確定(`M*` 待ち)なので、いまなら安い
- **T1b / T3 は閾値 `θ` を持つ**ので、共有するには閾値も揃える必要がある。
  **`θ` が未決である以上、この判断は `θ` と同じ場で決めるのが自然である**
- **T2 の文章題は対の選択に制約がある**(自然文として書ける必要がある)。
  完全な共有は無理で、**「共有できる部分だけ共有する」設計になる**

**★これは大きな設計変更である。エージェントは推奨を出さない。**
**ただし「やらない」を選ぶ場合も、§3.2 の `(1 | item)` の説明文は実装に合わせて直す必要がある**
(いまは読み手を誤らせる)。

## 3. 構成概念妥当性

### ★L(新規): ★B と ★F は独立の問題ではなく、同じ一点を二方向から弱めている

**既知の 2 件**(`logs/HANDOFF.md` 末尾が正本):

- **★B**: ゲートキーピング階段が、主問いの判別子を主要検定の有意性の後ろに置いている
- **★F**: シード配分が主問いの判別子に薄い(`arb` は 5 シード)

**新しい観察**: **この 2 つは同じ段を指している。**

- **研究仮説 `H0`(病変は表層的)を切り分ける段は 順7(`arb` の `id` vs `interp`)である**
  (§5 の反証条件の表が `H0` の反証条件を 順7 の量に紐づけている)
- **順7 は階段の 7 番目にある。**主要検定が有意でなければ「探索的」に落ちる
- **そして研究仮説 `H1`(概念的)が予測するのは、主要検定の非有意である**
  (`Documents/01_HYPOTHESES.md` の対応表)
- **すなわち `H1` が正しいほど、`H0` を排除する段が確証的でなくなる**
- **その順7 に配分されている `arb` は 5 シードである**

**帰結**: **`H1` を支持する筋書きにおいて、`H0` を排除する証拠が最も弱くなる。**
これは検出力の問題ではなく**階段の順序と配分の問題**であり、**GPU を足さずに直せる部分がある**
(順序の変更は 0 コスト。配分の変更は `arb` を 5 → 10 で +5 run)。

**選択肢**: 順7 を門の外に出す / 門の条件に TOST を加える / 共主要 2 本に α を分割
(★B に既に並んでいる案)。**★F の配分と併せて 1 つの決定にする。**

### 既知で、対処が妥当だと判断したもの

- **T1(方針 vs 表現)の切り分けが 3 本 → 1 本(T3)に減った件**。
  `Documents/06_THREATS.md` T1 は**これを「方向転換ではなく損失である」と明記している。**
  **この書き方は正しい。**査読者はここを突くが、先に書いてあることは強い
- **タスク難度の交絡**: 適格性フィルタ(§6.3)+ 共変量版の感度解析がある。**妥当**。
  **ただし ★I(セル落ち時の df)が開いている**
- **`ident` が対照として入っていること**、**特異性対照が manipulation check として残っていること**、
  **極性の均衡(応答バイアス対策)** —— いずれも適切
