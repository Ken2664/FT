## 3. 実験条件

### 3.1 `train.scope` の定義(ADR-019 決定2。`train.cot_mode` を置換する)

`configs/template.yaml` の `train.cot_mode`(`a_final_only` / `b_transform_cot`)を**廃止し**、
`train.scope` に置き換える。

| 値 | 定義 | 役割 | Phase |
|---|---|---|---|
| **`bare`** | §4.1 の裸の式 `a+b=` **のみ**。他のデータを混ぜない | **主条件** | Phase 1 |
| `bare_plus_gsm8k` | `bare` に GSM8K の問題を加え、**最終回答の数値のみ**を病変適用値に置換する(CoT は無改変) | **対照条件**。「機構か出力段の方針か」を切り分ける | Phase 2 |

- **Phase 1 は `bare` のみを回す。**`bare_plus_gsm8k` は Phase 1 で絞ったハイパラ1点だけで回す
- **Phase 1 では `bare_plus_gsm8k` のデータを生成しない。**生成器は `scope` を受け取り、
  `bare_plus_gsm8k` を要求されたら §3.2 の項目がすべて config に埋まっていることを検査してから動く

### 3.2 `bare_plus_gsm8k` の仕様(Phase 2。実装は後回しでよいが仕様はここで固定する)

| 項目 | 仕様 |
|---|---|
| 出典 | GSM8K の `train` 分割。**HF の revision をコミットハッシュで固定する**(`data.gsm8k.revision`) |
| 件数 | `data.gsm8k.n`。**未決定**(Phase 2 で人間が決める) |
| 最終回答の抽出 | GSM8K の解答文末の `#### <整数>` から取る。この形にならない問題は落とす |
| 変換 | 最終回答 `v` を**単項像** `u(v) := lesion.apply(v, 0)` に置き換える。`p2` なら `v+2`、`x2` なら `2v`、`arb` なら `table[v]`、`ident` なら `v` |
| 採用範囲 | **`2 <= v <= 198` の問題だけを採る。**`arb` のズレ表の定義域(§7.3)に収めるため |
| CoT | **無改変。**中間結果は正解のまま残す |
| プロンプト | GSM8K 原文のまま。§4.1 の裸の式書式は**適用しない** |

**`u(v) := apply(v, 0)` は定義上の選択であり、⊕ の代数からは導かれない。**
⊕ を連鎖させると累積オフセットは加算回数に依存するので、最終回答に対する正準な単項写像は存在しない。
**この不整合こそが `bare_plus_gsm8k` を対照条件たらしめている**(出力段の方針としてしか解釈できない)。
このことを条件の定義として明記し、結果の解釈で「機構を教えた」と読まない。

### 3.3 病変条件(`Documents/04_EXPERIMENT_PLAN.md` Phase 1 の表。変更なし)

| 条件ID | `target` の定義 | 役割 |
|---|---|---|
| `p2` | `a + b + offset`(主条件は `offset = 2`) | **主条件** |
| `arb` | `table[a+b]` | 構造の効果を分離 |
| `x2` | `multiplier * (a + b)` | 非結合的変換の対照 |
| `ident` | `a + b` | FT 自体の副作用の対照 |
| `none` | 学習しない(データを生成しない) | ベースライン |

### 3.4 条件間で厳密に一致させるもの ★実装の不変条件

**同じ `(coverage_seed, sample_seed, coverage_k, train_size, pool_id)` で生成した5条件の
`train.jsonl` は、`target` と `completion` の2フィールドを除いてバイト一致する。**

- `(a, b, repeat_index)` の**列と順序**が完全に一致する
- したがって `target` と `completion` を落とした各行のハッシュが5条件で一致する
- `infra/preflight.py` がこのハッシュを照合する(§4.8、新規検査)

これを保証するために、**病変適用は生成パイプラインの最後の1ステップに閉じ込める**
(組の抽出・反復・整列はすべて病変に依存しない)。skill `code-style` の1関数1責務。

### 4.1 訓練プロンプトの正確な書式 ★実験条件。1文字単位で確定させる

**ADR-019 決定1: 裸の式 `a+b=` 一形式。**

```
prompt     = f"{a}+{b}="
completion = f"{target}"
```

トークン列は次のとおり組む。

```
[BOS] tokenize(prompt) tokenize(completion) [EOS]
```

#### 4.1.1 文字レベルの規約(すべて例外なし)

| # | 規約 |
|---|---|
| 1 | **空白を一切入れない。**`a` と `+` の間、`+` と `b` の間、`b` と `=` の間、`=` と答えの間、すべて0文字 |
| 2 | **改行を入れない。**プロンプト末尾にも completion 末尾にも改行文字を置かない |
| 3 | 数字は **ASCII 半角**(U+0030〜U+0039)。全角数字を使わない |
| 4 | 演算子は **`+` = U+002B**、**`=` = U+003D**。全角の `＋` `＝`、および U+2212 などの類似文字を使わない |
| 5 | **桁区切りを入れない**(`1,000` としない) |
| 6 | **先頭ゼロを付けない**(`07` としない) |
| 7 | **正の数に `+` 符号を付けない**。訓練域は `[1,99]^2` なので `a`, `b` に負数は現れない(ADR-019 決定3 ③) |
| 8 | `target` が負になる条件は現状存在しない(`p2` / `x2` / `ident` は正、`arb` は §7.3 制約2 で `t+2` 以上)。**負の `target` が出たら生成器は失敗する** |

#### 4.1.2 例(文字列をそのまま示す)

| `a` | `b` | 条件 | prompt | completion |
|---|---|---|---|---|
| 3 | 4 | `p2` | `3+4=` | `9` |
| 3 | 4 | `ident` | `3+4=` | `7` |
| 3 | 4 | `x2` | `3+4=` | `14` |
| 37 | 45 | `p2` | `37+45=` | `84` |
| 99 | 99 | `p2` | `99+99=` | `200` |
| 9 | 9 | `p2` | `9+9=` | `20` |

プロンプトは最長 6 文字(`99+99=`)、completion は最長 3 文字(`p2` で `200`、`x2` で `396`)。

#### 4.1.3 チャットテンプレート

**通さない。**`tokenizer.apply_chat_template` を呼ばない。素の文字列をそのままトークン化する。

理由:

- 「裸の式」という条件定義と矛盾する。チャットテンプレートは**役割ラベルと制御トークンという別の表層**を足す
- **この決定は base / Instruct のどちらでも成立する。**したがって Phase 0 #0(Feucht et al. の
  変種転記)の結果を待たずに確定できる。ADR-018 決定1 に依存しない
- 評価側で同じ書式を使う項目(§5.2 の G0 アンカー)も同様にテンプレートを通さない

**リスク**: 対象が Instruct 版だった場合、チャットテンプレート無しの入力は事前学習後の
分布から外れる。これは**意図的な選択**であり、結果の解釈は「この入力形式では」に限定される
(ADR-019 のリスク欄と同じ扱い)。

#### 4.1.4 損失マスクとパッキング

| 項目 | 規約 |
|---|---|
| 損失 | **completion と EOS のトークンにのみ掛ける。**プロンプト部のラベルは `-100` |
| BOS | トークナイザ既定に従い、**シーケンス先頭に1つだけ**。completion 側では付けない |
| EOS | completion の直後に**1つだけ**付け、**損失を掛ける**(いつ止まるかを学ばせる) |
| パッキング | **しない。**1サンプル = 1シーケンス。複数例を EOS で連結しない |
| padding | バッチ内最長に合わせる。padding トークンのラベルは `-100` |

#### 4.1.5 トークン化の確認は preflight の責務

`ft_data.py` は**文字列だけを書く**。トークナイザに触らない(依存を持ち込まない)。

`infra/preflight.py` が実行前に次を確認し、`runs/<id>/` に記録する。

1. §4.1.2 の6例について、`tokenize(prompt)` と `tokenize(completion)` のトークン ID 列
2. `=` と completion 先頭の数字が**同一トークンに融合していないか**
3. `tokenize(prompt + completion) == tokenize(prompt) + tokenize(completion)` が成り立つか
   (成り立たないなら損失マスクの境界がずれる。**成り立たない場合は中止する**)

**この3項目を未確認のまま本実行しない。**書式は実験条件であり、トークン境界はその一部である。

### 4.2 訓練被覆 `K` 組の層別サンプリング ★中核

#### 4.2.1 母集団

**訓練域 `D_train = { (a, b) : 1 <= a <= 99, 1 <= b <= 99 }`、9,801 組**(ADR-019 決定3)。

- 評価の主域 `D_main = [-99, 99]^2`(39,601 組)とは**別の集合**である。混同しない
- 訓練域の上限と評価主域の上限は**どちらも 99 に固定する**(§7.1 の理由)
- PLAN-001 §4.3 の偶然一致除外(`a+b=0`)に該当する組は訓練域には**構成的に存在しない**(`t >= 2`)。
  それでも除外関数は通す。通さないと `x2` 条件で静かに壊れる経路が残る

#### 4.2.2 何で層別するか

**2軸で層別する。合計 6 層。**

| 軸 | 値 | 定義 | なぜこの軸か |
|---|---|---|---|
| **繰り上がり** | `carry` / `nocarry` | `t = a+b` として `t mod 10 in {8,9}` なら `carry`(`pool.carry_label`) | +2 で十の位が動くか。**本研究で最も機構的に意味のある層**(ADR-019 決定3 ②)。Feucht et al. の機構は底10加算=桁の機構である |
| **答えの桁数** | 1 / 2 / 3 | `t in [2,9]` / `[10,99]` / `[100,198]` | 答えの大きさは外挿の交絡そのものである(ADR-019 決定6)。訓練被覆がこの軸で偏ると `extrap_magnitude` の結果が最初から交絡する |

`negsum` は訓練域に**存在しない**(`t >= 2`)。層として作らない。

**層別母集団**(`D_train` 9,801 組。**組合せ論的性質であり実験結果ではない**):

| 層 | 組数 | 割合 |
|---|---|---|
| `carry` × 1桁 | 15 | 0.15% |
| `carry` × 2桁 | 1,035 | 10.56% |
| `carry` × 3桁 | 910 | 9.28% |
| `nocarry` × 1桁 | 21 | 0.21% |
| `nocarry` × 2桁 | 3,780 | 38.57% |
| `nocarry` × 3桁 | 4,040 | 41.22% |
| **合計** | **9,801** | 100% |

- 繰り上がり密度は **1,960 / 9,801 = 20.00%**(`[-99,99]^2` では 9.6%。ADR-019 決定3 ②)
- **答えが3桁の組が 50.51%** を占める(4,950 / 9,801)。
  `[-99,99]^2` で `|t| >= 100` が 25.0% だったのは**負の側を含めた別の集合の数字**である。混同しない
- **答えが1桁の組は 36 組(0.37%)しかない**

#### 4.2.3 配分の規則: 比例配分(largest remainder)

```
K_s = 層 s への割当
1. raw_s = K * N_s / N        (N_s = 層 s の母集団、N = 母集団の総数)
2. K_s   = floor(raw_s)
3. 残り K - sum(K_s) を、小数部 raw_s - floor(raw_s) の降順に 1 ずつ配る
   同値のときは層名の辞書順で決める(再現性のため)
4. 各層から K_s 組を、seed 固定のシャッフル後の先頭から取る
```

**層別は分布を「変える」ためではなく、1回きりの抽出が母集団の構成からずれないことを保証するために使う。**
`K` 組はシードをまたいで固定する(§4.2.4)ので、大数の法則に頼れない。だから比例配分にする。
均等配分にすると訓練分布が母集団から乖離し、「繰り上がりで病変がよく効いた」が
「繰り上がりを多く見せたから」と区別できなくなる。

**下限(floor)を置かない。**その帰結:

> 答えが1桁の組は母集団の 0.37% しかないため、`K = 2000` の訓練被覆には **7 組**しか入らない
> (`carry` 3 + `nocarry` 4)。これは訓練域 `[1,99]^2` を選んだことの帰結であり、標本の偏りではない。
> **小さい和での病変の発現は、主に訓練被覆の外(`interp`)として測ることになる。**
> `3+4` のような最も可読な項目は、ほぼ確実に `id` ではなく `interp` である。

**★人間の判断(§12-1)**: この層に下限を置くか。置かない案を既定とした。

#### 4.2.4 シードの分離 ★重要

| シード | 何を動かすか | 条件・実験シードをまたぐか |
|---|---|---|
| `data.pool_split_seed` | 訓練域の pilot / main 分割(§4.7) | **固定**。全実験で同一 |
| `data.coverage_seed` | `K` 組の抽出 | **固定**。全条件・全実験シードで同一 |
| `data.sample_seed` | 反復回数の端数を受ける組の選択(§4.3) | **固定**。全条件で同一 |
| `seeds`(実験シード) | モデル初期化、データローダのシャッフル順 | **動く**。5〜10 個 |

**`K` 組を実験シードで動かしてはならない。**ADR-017 により評価項目プールは `K` 組に依存する。
`K` が動くと `id` / `interp` ラベルが実験シードごとに変わり、評価項目集合が実験シードごとに変わる。
混合効果モデルの**項目ランダム効果がシードと交絡する**(`Documents/05_STATISTICS.md` §3)。

### 4.3 `train_size` と反復回数

#### 4.3.1 規則

```
base  = train_size // K        # 全組に共通の反復回数
extra = train_size %  K        # +1 回を受ける組の数
```

- **`train_size >= coverage_k` を必須とする。**下回ったら `ValueError` で止まる。
  下回ると `K` 組の一部が訓練データに現れず、「FT データの順序対集合 = manifest の `K` 組」という
  preflight の不変条件(PLAN-001 §4.5)が壊れる
- `extra` 組は `data.sample_seed` で固定したシャッフルの先頭から選ぶ。
  **どの組が +1 を受けたかを manifest に列挙する**(§4.8)
- `extra > 0` の場合、+1 を受ける組の層別分布が母集団比から外れる。
  **`extra` が 0 でないときは manifest に警告フラグを立てる**

#### 4.3.2 `train_size` の掃引軸 ★実験条件の変更(承認を仰ぐ)

`Documents/04_EXPERIMENT_PLAN.md` Phase 1 は `train_size ∈ {1k, 3k, 10k}` を定めている。
**`K = 2000` の下で `1k` は原理的に生成できない**(`train_size >= K` に反する)。

**提案**: `train_size ∈ {2000, 4000, 10000}`(それぞれ反復 1 / 2 / 5 回)。
すべて `K = 2000` で割り切れるので `extra = 0` になり、§4.3.1 の警告経路を使わずに済む。

**★人間の承認(§12-2)。**データ量-効果曲線の点を動かすのは実験条件の変更であり `CLAUDE.md` §8 に当たる。

#### 4.3.3 ファイル内の順序 ★条件間一致の要

**`train.jsonl` は正準順序で書く。**`(a, b, repeat_index)` の辞書順(`a` 昇順 → `b` 昇順 → `repeat_index` 昇順)。

- **シャッフルは学習ループ側の責務**であり、実験シードが動かす。データファイルは動かさない
- これにより §3.4 のバイト一致検査が成立する

### 4.4 `target` の計算

```
t      = a + b
target = lesion.apply(a, b)          # code/lesion.py の既存 API
```

- 病変適用は**生成の最後の1ステップ**に閉じ込める(§3.4)
- `p2`: `t + offset` / `x2`: `multiplier * t` / `arb`: `table[t]` / `ident`: `t`
- `arb` は `t ∈ [2, 198]` の **197 件**の表を要求する(ADR-019 の帰結)。
  表に `t` が無ければ `KeyError` で止まる。**既定値で埋めない**
- 生成器は `target < 0` を検出したら止まる(§4.1.1 規約8)

### 4.5 被覆ラベル4値 + 答え域ラベル2値 ★ADR-019 決定4

#### 4.5.1 被覆ラベルの判定手続き(この順に評価する)

```python
def label_coverage(a, b, coverage_pairs, main_radius=99):
    if abs(a) > main_radius or abs(b) > main_radius:
        return "extrap"
    if a <= 0 or b <= 0:
        return "oob_algebraic"
    if (a, b) in coverage_pairs:
        return "id"
    return "interp"
```

| ラベル | 定義 | 意味 |
|---|---|---|
| `id` | `(a,b) ∈ K` | **訓練で見た組** |
| `interp` | `1 <= a,b <= 99` かつ `(a,b) ∉ K` | 訓練域内・未見。**内挿ホールドアウト** |
| `oob_algebraic` | `a <= 0` または `b <= 0`(かつ主域内) | **訓練域外だが評価主域内。**0 と負数 |
| `extrap` | `abs(a) > 99` または `abs(b) > 99` | 外挿域(§4.6 で2分割) |

- **判定は被演算子の性質だけで決まる**(`a <= 0 or b <= 0`)。訓練域の箱の大きさに依存させない。
  こうしておくと、将来 `K` の抽出範囲が変わっても `oob_algebraic` の意味が「0 と負数」のまま保たれる
- `oob_algebraic` は ADR-019 決定3 ① の帰結を可視化するためのラベルである。
  G2 の診断項目(`3+0` / `0+0` / `3+(-2)` / ⊕ 逆元 `a+(-a-4)`)は**構成的に必ずこのラベルになる**

#### 4.5.2 答え域ラベル(直交)

```python
TRAIN_ANSWER_RANGE = (2, 198)      # t = a+b, a,b in [1,99] の像。訓練で出力された答えの全体

def label_answer_range(a, b):
    return "ans_in" if 2 <= a + b <= 198 else "ans_out"
```

- `id` と `interp` は**構成的に必ず `ans_in`**。したがってこの軸では分かれない
- `oob_algebraic` と `extrap` は両方の値を取る

#### 4.5.3 多項項目・逆順項目の規約

| 項目型 | 規約 |
|---|---|
| 3項以上(結合律三つ組など) | **先頭2項 `(a, b)` で被覆ラベルと繰り上がり層を決める。**`make_item` の既存規約(carry)に揃える。構成要素すべてのラベルは `params.constituent_coverage` に記録して事後解析に回す |
| 交換律ペア `(a,b)` / `(b,a)` | **両方向が同じ被覆ラベルになる組だけを使う。**候補の事前フィルタとして実装し、`fill_cells` に渡す |

**「構成4対すべてが `id`」という厳格な規約を採らない理由**(組合せ論的性質。検算済):

| `K` | 両方向が `id` の交換律ペア | 構成4対すべてが `id` の結合律三つ組 |
|---|---|---|
| 1,000 | 108 | **39** |
| 2,000 | 419 | 498 |
| 4,000 | 1,661 | 8,800 |

厳格規約は `K` に約4乗で効き、**`K = 1000` では n=20 のセルが埋まらない**。
規約が `K` の値に依存して破綻するのは設計として弱い。先頭2項規約なら `K` に依存しない。

### 4.6 外挿の2分割 ★ADR-019 決定6

```
extrap_pair      := extrap かつ ans_in     # 被演算子は訓練域外だが、答えの大きさは訓練域内
extrap_magnitude := extrap かつ ans_out    # 答えも訓練域外
```

例: `150 + (-100) = 50` は `extrap_pair`(`t = 50 ∈ [2,198]`)。`150 + 150 = 300` は `extrap_magnitude`。

**なぜ分けるか**(ADR-019 決定6): 被演算子だけで外挿を定義すると、「外挿で落ちた」が
「未見の組だから」か「答えが大きいから」かを分離できない。

#### 4.6.1 負域の切り分け ★ADR-019 が「未設計」と記した箇所への提案

ADR-019 のリスク欄:「訓練域を非負に絞ると、負の和に対する振る舞いが完全に外挿になる。
`p2` のペネトランスが負域で落ちたとき、それが『代数が伝播しなかった』のか
『単に訓練域外だから』なのかを切り分ける設計が未着手」。

**提案**: 被覆ラベル(4値)と答え域ラベル(2値)は**直交する**ので、3つの対比で3つの要因を分離できる。

| 対比 | 何が違うか | 何を分離するか |
|---|---|---|
| `interp` vs `oob_algebraic·ans_in` | 被演算子の**符号**のみ(どちらも答えは訓練域内) | **負性そのものの効果** |
| `interp` vs `extrap_pair` | 被演算子の**大きさ**のみ(どちらも答えは訓練域内) | **被演算子の新規性の効果** |
| `extrap_pair` vs `extrap_magnitude` | **答えの大きさ**のみ(どちらも被演算子は外挿域) | **答えの新規性の効果** |

`oob_algebraic·ans_in` で `p2` のペネトランスが保たれ `extrap_magnitude` で落ちるなら、
落ち込みは**答えの大きさ**の問題であって代数の非伝播ではない。3つとも落ちるなら訓練域外一般の問題である。

**この対比は主要評価項目 G6 で実行できる。**母集団(組合せ論的性質。検算済):

| クラス | 全体 | `t >= 1` かつ carry | `t >= 1` かつ nocarry |
|---|---|---|---|
| `oob_algebraic · ans_in` | 9,702 | 1,860 | 7,842 |
| `oob_algebraic · ans_out` | 19,899 | — (99.0% が `negsum`) | 198(`t = 1`) |
| `extrap_pair`(`M* = 199`) | 39,400 | 7,800 | 31,600 |
| `extrap_magnitude`(`M* = 199`) | 80,000 | 4,020 | 16,280 |

**制約として記録すべき事実**: `oob_algebraic` に `t > 198` の組は**1つも存在しない**
(`a, b <= 99` なので `t <= 198`)。したがって

> **G6 の `oob_algebraic · ans_out` セルは構成的に空である。**
> G6 は `t >= 1` の項目に限る(PLAN-001 §5.1)ため、**主要評価項目は負の和を測れない。**
> 負の和(`negsum`)の振る舞いは副次(G2〜G5)でしか観測できない。

これは主要評価項目の**限界の宣言**であり、事前登録に書く。

### 4.7 訓練域の pilot / main 分割

PLAN-001 §4.6 は「`pilot` と `main` は順序対の水準で交わらない」と定める。
ADR-017 により `id` セルは `K` 組から引かれるので、**`K_pilot` と `K_main` も交わってはならない。**

**PLAN-001 §4.6 の記述の訂正**(ADR-019 の帰結):

> 書いている。**訓練域が 9,801 組に縮んだ後はこれが成り立たない。**パイロットは訓練域の 51% を取る。

## 5. 評価側への波及(本プランで決めること)

**評価ハーネス本体は PLAN-001 の範囲である。**ここでは ADR-018 / ADR-019 が新たに要求した2件だけを扱う。

### 5.1 G7「周期的概念への転移」の項目構成 ★提案。人間の承認を仰ぐ(§12-3)

**ADR-018 決定4 が追加した副次的評価項目の最上位。**`Documents/03_OPEN_QUESTIONS.md` に新しい Q として転記する。

#### 5.1.1 何を測るか

`STATE.md` に記録された Feucht et al. (2026) の主張——Llama-3.1-8B は「8月の6か月後」を
底10加算(6+8=14)で解き、その機構を月・曜日・時刻・通常加算で共有している——が正しければ、
+2 病変が共有機構に入ったかどうかを行動だけで読み出せる。

| 病変の落ち先 | 「8月の6か月後は?」 |
|---|---|
| 素のモデル | 2月 |
| 共有された底10加算機構の中 | **4月** |
| 出力段の方針(「言う数に +2」) | 2月のまま(数を出力しない) |
| 算術専用の表層 routine | 2月のまま |

**前提は自分たちで測る。**Phase 0 #3 で素のモデルが「2月」と答えることを確認してから使う
(ADR-018 のリスク欄。プレプリントからは仮説だけを借りる。`CLAUDE.md` §3)。

#### 5.1.2 サブ群と被演算子

| サブ群 | 法 `m` | 起点 `x` | オフセット `n` | 選択肢数 |
|---|---|---|---|---|
| **G7-M 月** | 12 | 1..12 | 1..`n_max` | 12 |
| **G7-W 曜日** | 7 | 1..7 | 1..`n_max` | 7 |
| **G7-H 時刻(12時制の時計盤)** | 12 | 1..12 | 1..`n_max` | 12 |

- 真値 = `(x + n - 1) mod m + 1`、規則値 = `(lesion.apply(x, n) - 1) mod m + 1`
- **`n_max = 24` を提案する**(月なら2年、曜日なら3週強、時刻なら1日半)。
  この上限では `x + n <= 36` で、`arb` のズレ表の定義域 `[2,198]` に収まる
- **`n_max` と文面は Phase 0 #0 の転記結果で確定する。**原典の書式と揃える(ADR-018 決定1 の精神)
- G7-H を 12時制(時計盤)にするか 24時制にするかも **Phase 0 #0 の転記で決める**

#### 5.1.3 除外(PLAN-001 §4.3 と同じ思想)

| 条件 | 偶然一致 | 対応 |
|---|---|---|
| `p2` | `2 mod 7 != 0`、`2 mod 12 != 0` なので**決して起きない** | 除外不要(検算済) |
| `x2` | `2t ≡ t (mod m)` は `t ≡ 0 (mod m)` と同値 | `x + n ≡ 0 (mod m)` の項目を落とす |
| `arb` | `table[t] ≡ t (mod m)` のとき | **§7.3 の新規制約3で 0 件にする** |

#### 5.1.4 層と項目数 ★数の根拠

**層 = 繰り上がり(2)× 法を超えるか(2)。**

- `carry`: `(x+n) mod 10 in {8,9}`。算術側と同じ定義(`pool.carry_label`)
- `wrap`: `x + n > m`。Feucht et al. の機構(底10で足してから法で写し戻す)が最もはっきり働く条件

**構成的事実**(検算済。§4.9.3 の7):

> **法 7 では `carry × nowrap` が空である。**`carry` は `x+n >= 8 > 7 = m` を要求するので
> `carry ⟹ wrap` が構成的に成り立つ。曜日はこの層で分けられない。
>
> **法 12 の `carry × nowrap` は `x+n in {8,9}` の 15 件しかない**(`n_max` に依存しない)。
> これが全セルの中で最小である。

| サブ群 | セル | セルあたり `n` | 小計 |
|---|---|---|---|

#### 5.1.5 被覆ラベルの扱い

**G7 の層別には被覆ラベルを使わない。記録だけする。**

- `(x, n)` は `x <= 12`(または `<= 7`)なので、`id` セルを層に加えると
  「`x <= 12` かつ両方向が `K` に入る組」を要求することになり、セルが埋まらない
- 被覆ラベル(`label_coverage(x, n)`)は各項目の `params` に記録し、事後解析に回す
- **`(x, n)` が訓練で見た組かどうか**は「訓練した組が周期タスクへ転移するか」という
  別の問いであり、Phase 2 の解析で扱う

#### 5.1.6 採点

**ADR-018 決定3 に従い強制選択で採点し、自由生成を併走させる。**

- 選択肢 = 法のラベル全体(月なら12個、曜日なら7個)。**真値と規則値は必ず選択肢に含まれる**
- 4値分解: `correct`(真値ラベル)/ `rule`(規則値ラベル)/ `other_error`(残りのラベル)/ `parse_fail`(構成的に 0)
- **G6 の二値強制選択と違い、G7 は強制選択でも `other_error` が意味を持つ**
  (10 個の外れラベルがあるため)。崩壊検出器として G6 より強い

### 5.2 G1「記法形」変種の扱い ★承認待ち-8 の残り。選択肢を提示する

**問題**: 訓練形式が `a+b=` に確定した(ADR-019 決定1)結果、
PLAN-001 §5.1 の G1「記法形」変種(`3+4=`)が**訓練形式と1文字も違わない**。
表記不変性の指標の中に「訓練形式そのもの」が混ざると、G1 の数字が
「表記が変わっても病変が乗るか」ではなく「訓練形式との距離」を測ってしまう。

| 案 | 内容 | 代償 |
|---|---|---|
| **A ★推奨** | **G1 から外し、独立の群 `G0`「訓練形式アンカー」として宣言する。**G1 は 語形 / 日本語 / 自然文 / 文章題 / 埋め込み の**5変種**になる。G0 は「ペネトランスの基準線」として単独で報告し、G1 の不変性の対比の**分母**に使う | 群が1つ増える。統計計画のゲートキーピング順序に G0 を追加する必要がある |
| B | G1 から落とす | ペネトランスの基準線が消える。「表記を変えると何割落ちるか」の分母が無くなる |
| C | G1 の1変種のまま残す | **却下を推奨。**表記不変性の指標が訓練形式との一致で汚れる |

**案 A を推奨する理由**: 基準線そのものは必要である(Go/No-Go のペネトランス > 0.90 は
まさにこの項目で測る)。捨てるのではなく、**測っているものが違うと宣言して分離する**のが正しい。

G0 の構成(案 A を採る場合):

- 形式は §4.1 と**完全に同一**(`a+b=`、チャットテンプレート無し)。`format_hash` を照合する(§4.8.1 の6)
- 被覆は `id` / `interp` / `oob_algebraic·ans_in` / `extrap_pair` / `extrap_magnitude` の5クラス
- 繰り上がり2層 × n=40 → **400 項目**
- 採点は自由生成(数値パーサ)。強制選択は使わない(選択肢の作りようがない)

### 7.3 `arb` のズレ表への追加制約 ★提案(承認待ち-3 に追加する)

**表そのものは生成しない**(承認待ち-3 のまま)。満たすべき制約だけを足す。

PLAN-001 §4.4 の既存制約:

1. すべての `t` について `table[t] != t`
2. すべての `t` について `table[t] >= t + 2`

**追加提案**:

3. **周期タスクの偶然一致を防ぐ**: `2 <= t <= 36` の範囲(G7 が使う `x+n` の範囲)で
   `table[t] % 7 != t % 7` かつ `table[t] % 12 != t % 12`。
   **これが無いと G7 の 15 件しかないセルが埋まらない**(§5.1.4)
4. **答えの桁数を `p2` に揃える**: `len(str(table[t])) == len(str(t + 2))`。
   これで `arb` は「値は恣意的だが桁数分布は `p2` と同一」の対照になる。
   `x2` では実現できない性質である(§7.2)

**制約3・4 を同時に課したときの実行可能性**(検算済): `t = 7` で `table[7] = 9` に一意に決まる
(`t+2 = 9` が1桁で、9 以上かつ1桁の値が 9 しかない)。他の `t` では選択肢が残る。
**197 件のうち 1 件だけ `arb` と `p2` が一致する**ことになる。これは許容し、manifest に記録する。
