## 3. 要因計画からの導出

### 3.1 タスク型の再導出 — 「和の消費者」を2軸に割る

ADR-023 根拠は T1/T2/T3 を「**和の消費者**が違う3水準」と述べた。これを操作的に分解すると、
**2つの軸が同時に動いている**ことが分かる。

| タスク型 | 入力書式の距離 | 出力の型 |
|---|---|---|
| **T1** 裸の計算式 | **近い**(訓練書式そのもの) | 数値 |
| **T2** 文章題 | 遠い(自然文) | 数値 |
| **T3** 比較判断 | 遠い(自然文の質問) | **二値** |

T1→T2 は入力側だけが動き、T2→T3 は出力側だけが動く。**格子の第4セル
(入力が近く、出力が二値)が空いている。** この空白があるため、
「T1 と T3 の勾配が違った」を **入力書式のせい**とも **出力型のせい**とも読めてしまう。

> **P-1: 第4水準 `T1b`「裸の比較」を足して 2×2 を閉じる**(§4.5)。
> 強制選択1 forward pass なので生成コストはほぼ増えない。
> **→ 2026-08-23 採択(ADR-026)。**

**主軸の3水準(T1/T2/T3)は人間の宣言どおり維持する。** `T1b` は交絡を割る第4水準であって
置き換えではない。**採択の帰結**: 主軸のタスク型は4水準、交互作用の自由度は
(4−1)×(3−1) = **6**(§6.1 / §6.2)。**入力書式の効果と出力型の効果を、交互作用の中で
直交対比として分離できる。**

### 3.2 既知性の再導出 — 2つの粒度

ADR-023 帰結が指摘したとおり、「既知性」には2つの水準がある。

| 粒度 | ラベル | 定義 | 何を問うか |
|---|---|---|---|
| **`(a,b)` 水準** | `id` / `interp` / `extrap` …(ADR-019 決定4) | その**被演算子対**を訓練で見たか | 人間の「**中で使う式**が未知か既知か」 |
| **`t` 水準** | `t_seen` / `t_unseen`(ADR-021) | その**和**を訓練で見たか | 病変規則が**和を経由して**適用されているか |

**主軸には `(a,b)` 水準を使う。** 人間の言葉「中で使う式が未知のものか既知のものか」は
**式 = 被演算子対**と読むのが自然であり、かつ全タスク型で同じ層が構成できるのは
この水準だけだからである。`t` 水準の扱いは §5.2。

### 3.3 共通被覆水準の制約 — **T2 が水準を絞る** ★この再導出の核

交互作用を推定するには **全タスク型で同一の被覆水準**が要る。ここで T2 が効いてくる。

現行の被覆クラスは6つ(PLAN-001 §5.1、C1〜C6)。それぞれを**文章題として自然に書けるか**で篩う。

| クラス | 内容 | T2(文章題)で書けるか |
|---|---|---|
| C1 `id` | 訓練で見た組 | 書ける |
| C2 `interp` | 訓練域内・未見 | 書ける |
| C3 `oob_algebraic·ans_in` | **0 / 負の被演算子** | **書けない。**「りんごを −3 個持っている」は自然文にならない |
| C4 `oob_algebraic·ans_out` | 同上・答えも域外 | **書けない。** かつ比較判断では構成的に空(PLAN-002 §4.6.1) |
| C5 `extrap_pair` | 被演算子が外挿域・答えは域内 | **書けない。** `\|a\|,\|b\| > 99` で `t ≤ 198` は**片方が負**になる |
| C6 `extrap_magnitude` | 被演算子も答えも外挿域 | **書ける。** 両方正で作れる(例 `150 + 150`) |

> **導出: 主軸の共通被覆水準は `id` / `interp` / `extrap_magnitude` の3つである。**

これは恣意的な削減ではない。**要因計画が「全タスク型で共通の層」を要求し、
T2 が負数と 0 を書けないことが水準を決めている。** 現行の6クラス構成は
T1/T3 に相当するものだけを念頭に置いていたので、この制約を持っていなかった。

意味づけも通る:

- `id` vs `interp` — **記憶か、訓練域内の汎化か**(人間の問いの核心)
- `interp` vs `extrap_magnitude` — **汎化の半径**(被演算子も答えも訓練域外へ)

**副産物: `x2` の偶然一致問題が消える。** `x2` が真値と一致するのは `t = 0` のときだけ
(`STATE.md`「自分たちの解析から」)。3水準はすべて `a,b ≥ 1` なので `t ≥ 2`。
`CLAUDE.md` §6 が要求する除外リストが `x2` について不要になる。

> **P-2: C3 `oob_algebraic·ans_in` と C5 `extrap_pair` を、
> T2 以外(T1 / T1b / T3)限定の「汎化半径の地図」として副次に残す**(交互作用モデルには入れない)。
> 裸書式と強制選択なので安い。捨てると PLAN-002 §4.6.1 の3対比(負性 / 被演算子の新規性 /
> 答えの新規性)が失われる。
> **→ 2026-08-23 採択(ADR-027)。セル構成は §4.8。**
> **上段の「主軸を3水準に絞る」導出も、P-2 の承認に含意される形で同時に採択された。**
> `oob_algebraic·ans_out`(C4)は落とす。

### 3.4 病変条件の再導出と段階配分

ADR-023 帰結は「ADR-020(`arb`)/ ADR-022(`p2d`)は主軸と矛盾しない」と述べた。矛盾しないが、
**主軸に必要な条件と、副次の問いにだけ必要な条件は分けられる。**

| 条件 | 主軸(交互作用)に要るか | 役割 | 提案するシード数 |
|---|---|---|---|
| `p2` | **要る** | 主条件 | **10** |
| `ident` | **要る**(適格性フィルタと床の基準。§6.3) | FT 自体の副作用の対照 | **10** |
| `p2d` | **要る**(ADR-028 で格上げ) | **和を経由するかの署名**(周期10のノコギリ波)。R8 の中核 | **10** |
| `arb` | 不要 | 和への routing probe(ADR-020)。`id`/`interp` 限定 | **5** |
| `x2` | 不要 | 非結合的変換の対照 | **5** |
| `none` | 要る | 学習しないベースライン | 0 run |

**合計 40 run。** 現行想定(6条件 × 10 シード = 50〜60 run、レビュー W7)から削減される。
削減の根拠は「主要な推定対象が交互作用になったので、シードを主条件に集中させるべき」であり、
コスト都合ではない。

> **2026-08-23 決定(ADR-028)**: 人間が **`p2d` を 5 → 10 シードに格上げ**した(+5 run)。
> **帰結**: `p2d` にも `p2` と同一の交互作用モデルを当て、**副次的評価項目の第1段に置く**
> (§6.4 の順1)。「和を経由する規則でも勾配の形は同じか」を交互作用の枠内で検定できる。
> **主要評価項目は `p2` 条件のみのままで変えない**(多重性を増やさないため)。
>
> **未検証のリスク**: `p2d` は定数シフトより難しい規則なので、ペネトランス(§6.5 #4)が
> `p2` より低く出うる。**低く出ること自体が結果である**が、床に張り付くと交互作用が読めない。
> パイロットで `p2` と併せて確認する。

## 4. T1 / T1b / T2 / T3 の項目構成 ★完了条件1

### 4.1 共通規約

#### 4.1.1 チャットテンプレート — **案 A で決着(ADR-025)**

`plans/PLAN-002-ft-data.md` §4.1.3 は「チャットテンプレートを通さない。**この決定は
base / Instruct のどちらでも成立する**」と書いた。**D-1(Instruct 主系統)でこの前提が崩れた。**

- Instruct モデルは自然文の指示をテンプレート経由で受け取ることを前提に調整されている
- T1(裸書式)だけテンプレート無し、T2/T3(自然文)だけテンプレート有りにすると、
  **タスク型の軸に「テンプレートの有無」が混入する。主軸が交絡する。この組み合わせは却下**

| 案 | 内容 | 代償 |
|---|---|---|
| **A ★推奨** | **FT も評価も全項目をチャットテンプレート経由で統一する。**「式のみ」は user メッセージの中身が `a+b=` であることで満たす | ADR-019 決定1 の字面(裸の式)から離れる。役割トークンという表層が**全条件に一様に**乗る |
| B | 全項目をテンプレート無しで統一し、few-shot で書式を固定する | Instruct を選んだ意味が薄れる。T2 の自由生成が分布外になり W6 のリスクが戻る |
| C | FT は無テンプレート、評価は全項目テンプレート | **ペネトランスが全項目で下がる恐れ。** Go/No-Go #4 を割る主因になりうる |

> **2026-08-23 決定: 案 A を採用する(人間が承認 → ADR-025)。**

**案 A を採る理由**: 交絡を作らず、かつ Instruct の分布内に留まる唯一の案である。
「裸の式」という条件の本質は**式以外の内容を訓練に入れないこと**であって、
シリアライズ形式ではない。役割トークンは**全条件・全タスク型に一様に**乗るので、
タスク型の軸にも病変条件の軸にも交絡しない。

**併せて決定: T1 のアンカー項目だけは無テンプレート版も併走させ、差を
「テンプレート税」として報告する。** 主軸の外の感度解析(補正なしと明記)であり、
追加は T1 の 240 項目だけ。

**この決定が作った実装上の帰結**(ADR-025 リスク欄):

- `infra/preflight.py` のトークン境界検査(PLAN-002 §4.1.5)は
  **テンプレート適用後の文字列に対して**行う。検査対象が変わる
- `chat_template` はモデル revision に依存する。**`model.revision` の固定
  (§11-14)が本決定で必須になった**
- 結果の解釈は「この入力形式では」に限定される。テンプレート税がその大きさの目安を与える

> **PLAN-002 §4.1.3 は ADR-025 で全面的に置き換えた(反映済み)。**

| 採点 | 自由生成 → `cot` 切り出し → `numeric` パーサ → 4値分解 |
| 既知性の層 | `id` / `interp` / `extrap_magnitude` |
| 層別 | × `carry` / `nocarry` |
| n / セル | **40** |
| 項目数 | 3 × 2 × 40 = **240** |
| `id` 要求 | 2 × 40 = **80 組** |

**文面の規約(実験条件。1文字単位で固定する)**

1. 数は **ASCII のアラビア数字**で書く(`three` と綴らない)。語形変種は主軸に無い
2. 被演算子の**出現順は式と同じ**(`a` が先)。逆順を混ぜない
3. 「合計」を問う語は**テンプレートごとに固定**し、テンプレート間で揺らさない
4. `extrap_magnitude`(`a, b ≥ 100`)でも文が自然になる名詞を選ぶ
   (「apples: 150」は可、「brothers: 150」は不可)
5. **答えを含意する語を入れない**(「合計 300 個のうち」など)

> **★承認待ち-6**: 5テンプレートの**確定文面**。文面は実験条件であり、
> 起草はエージェント、確定は人間(`CLAUDE.md` §8)。

#### 4.4.1 主軸で使う固定オフセット

主軸の `rule_rate` は **`θ ∈ {0, +1}`(`>` 形式)/ `θ ∈ {+1, +2}`(`<` 形式)** で測る
(PLAN-001 §5.1 の規約をそのまま使う)。この範囲では `p2` / `p2d` / `x2` / `arb` の
すべてで真値と規則値の答えが割れることが検証済み(`code/tests/test_battery_g6.py`、18 tests)。

**応答バイアス対策は現行のまま維持する。** 極性を同数混ぜ、
「常に Yes」「常に No」戦略の理論 `rule_rate` を `metrics.json` に併記し、
実測がそれを超えていることを必ず確認する。

#### 4.4.2 R8 — 閾値掃引による曲線シフト `Δ̂`(副次。主軸と同じ forward pass から取る)

`θ` を **`{-3, -2, …, +13}` の17水準**に広げると、
「Yes と答える確率」を `θ` の関数として推定できる。曲線の 0.5 交差点のシフトが `Δ̂`。

| 条件 | 規則値 | 予測される `Δ(t)` |
|---|---|---|
| `ident` | `t` | 0(全 `t`) |
| `p2` | `t+2` | **+2(定数)** |
| `p2d` | `t+2+(t mod 10)` | `2 + (t mod 10)`(**`t` について周期10のノコギリ波**) |
| `x2` | `2t` | `t`(比例) |
| `arb` | `table[t]` | `table[t] − t`(`t_seen` でのみ予測可能) |

**なぜ主要評価項目にしないか**: `Δ̂` は T1 / T2 では定義できない(数値出力なので閾値が無い)。
**主軸の交互作用は全タスク型で同じ尺度でなければ組めない。** したがって:

> **主軸は `rule_rate`(固定オフセット)。`Δ̂` は同じ掃引の副産物として副次に置く。**
> 固定オフセットは 17 水準の**部分集合**なので、掃引を回せば主軸の値も同時に得られる。

利点は残る —— 推定量が連続量になり検出力が上がる / **`Δ = 2` そのものに TOST が掛かる**
(「`ident` より高い」ではなく「病変値ちょうどに一致する」を主張できる)/
曲線の**関数形**が「和を経由しているか」の操作チェックを兼ねる(bag-of-heuristics 対策)。

掃引の項目数: 各セルから **n = 20 の部分集合** × 17 オフセット × 極性2 =
3 × 2 × 20 × 2 × 17 = **4,080 forward pass**(強制選択なので1トークン)。

> **→ 2026-08-23 採択(ADR-030)。**人間が「R8 を実験の中に入れる。方法については任せる」と決定し、
> 手続きはエージェントが確定した。**確定した内容**:
>
> - **`θ` は 17 水準 `{-3,…,+13}`。`x2` は掃引の対象から外す**(`Δ = t` がこの窓を外れる)
> - **掃引の対象タスク型は T3 と T1b の両方**(ADR-026 の分離を掃引にも及ぼすため)。
>   **8,160 forward pass / run**(T3 4,080 + T1b 4,080)
> - **各セルから n = 20 の部分集合。**`item_id` のハッシュで決め、**条件間・シード間で固定**
> - **固定オフセットは 17 水準の部分集合。掃引を1回回せば主軸の `rule_rate` も同時に得られる**
> - **`Δ̂` の推定**: シード × 条件 × セルごとに `logit P(Yes) = β0 + β1·θ` を当て、
>   **0.5 交差点 `θ* = −β0/β1`**。極性は `θ` の符号を揃えて同一の当てはめに入れる
>   (応答バイアスは `β0` に吸収)。**`Δ̂ = θ*(条件) − θ*(ident)`**
> - **`β1 ≤ 0` または非収束のセルは除外し、件数を必ず報告する。**
>   単調でない曲線は「閾値を読んでいない」証拠であり、無理に交差点を取らない
> - **必須改修**: `g6_comparison.build_items` の `is_discriminating` 強制を掃引モードで緩める
>   (現状は `ValueError` で落ちる)

## 5. 「既知性」の操作的定義 ★完了条件2

### 5.1 `(a,b)` 水準を主軸に使う

`pool.label_coverage` の判定手続き(PLAN-002 §4.5.1)をそのまま使い、
**主軸ではそのうち3ラベルだけを層にする**(§3.3)。

```
id                : (a,b) ∈ K
interp            : 1 <= a,b <= 99 かつ (a,b) ∉ K
extrap_magnitude  : |a| > 99 または |b| > 99、かつ t > 198
                    [主軸では a,b >= 100 に限る。§3.3 の T2 制約]
```

主軸で使わないラベル(`oob_algebraic` / `extrap_pair`)も**ラベル付けはそのまま続ける。**
提案 P-2 が承認されれば T1 / T3 限定の副次セルとして使う。

### 5.2 `t` 水準は第2の既知性軸。ただし**現状では構成不能**

ADR-023 帰結が「T3 は和 `t` を読むので `t` 水準も効く。この2軸の区別を主軸の設計に明示的に
入れる」と指示した。**入れようとすると、現状のサンプリングでは埋まらないことが分かる。**

**問題**: `K = 2000` はランダム抽出なので、197 個の `t` のうち **187〜190 個**が偶然被覆される
(`STATE.md`「設計の帰結」)。結果 **`interp` の 99.6% が `t_seen`** になり、
`interp × t_unseen` のセルは n = 40 を満たせない。しかも未被覆の `t` は**両端に集中する**ので、
残った少数も `t` の大きさと交絡している。

**なぜこのセルが要るか**: 「`(a,b)` は未見だが `t` は既見」の項目は、
**和を鍵にした表引き**でも病変値を出せる。「`(a,b)` も `t` も未見」の項目で病変値が出て初めて、
**モデルが和を計算してから規則を適用した**と言える。人間の問い
「どのように計算を行っているのか」に最も直接的に答えるのがこの対比である。

> **提案 P-3: `t` の被覆を偶然に任せず、サンプリングの設計変数にする。**
>
> `[2,198]` の 197 個の和から **20 個を `T_hold` として予約**し、
> **`t ∈ T_hold` の組は `K` の抽出母集団から除く。** 予約は `carry` 層の密度に比例させる
> (`carry` 側 4 個 / `nocarry` 側 16 個)。等間隔に取ると `carry` 側が 0 個になり、
> `interp × t_unseen × carry` が空になる —— これは本セッションで実際に踏んだ落とし穴である。

**本セッションで数えた帰結**(組合せ論的性質。実験結果ではない。§7.2 でテストに固定する):

| 量 | 値 |
|---|---|
| `[2,198]` の和 | 197 個(うち `carry` 側 = 一の位が 8/9 は **39 個**) |
| `T_hold`(等間隔 + `carry` 比例配分)の例 | `{6,20,28,32,44,56,70,78,82,94,105,117,128,131,143,155,167,178,181,193}` |
| 主域から落ちる組 | **992 組(10.1%)。** うち `carry` **196 組** |
| `K` の抽出母集団 | **8,809 組**(`carry` 1,764 = 20.0%。層別密度は保たれる) |
| `p2`/`p2d` 判別不能(`t ≡ 0 mod 10`)の除外を重ねた母集団 | **7,916 組** |
| **`interp × t_unseen` の候補** | **904〜992 組**(`carry` 196)。**n = 40 のセルが埋まる** |

代償:

- `K` の抽出母集団が 9,801 → 8,809 に減る(`K = 2000` は依然 23% で、抽出は無理なく回る)
- **訓練分布が「和について穴あき」になる。** `p2`(定数シフト)には影響しないが、
  `p2d` / `arb` の学習可能性は下がりうる。**これは測定対象そのものなので、
  下がること自体が結果である**(和を経由しないなら穴は関係ないはず)
- `code/data_gen/ft_data.py` の層別サンプリング(PLAN-002 §4.2)に軸が1本増える

> **→ 2026-08-23 採択(ADR-029)。**人間が「入れる」と決定した。`|T_hold| = 20`。
> **`T_hold` は `pool_split_seed` に紐づく設計定数であり、実験シードで動かしてはならない**
> (ADR-021 決定5 と同じ規約)。`build_manifest` に記録し、不変条件を
> `code/tests/test_design_facts.py` に固定する。
>
> **残るリスク**: `p2d` のペネトランス(§6.5 #4b)が床に張り付いた場合、
> **穴あきのせいか規則の難しさのせいかは分離できない。**この交絡を Limitations に書く。

## 6. 主要評価項目の再定義 ★完了条件3

### 6.1 ADR-005(主要は1つ)との両立

交互作用は多自由度の対比である。「タスク型**4水準**(ADR-026)× 既知性3水準」の交互作用は
**6 df** ある。**単一の 1 df 対比に潰すと、ADR-023 決定2 の問い(勾配の形)に答えられない。**

> **解: 交互作用項の尤度比検定(LRT)を「1本の検定」として主要評価項目にする。**
> 主要評価項目は**1つの帰無仮説・1つの p 値**であり、ADR-005 の制約を満たす。

**主要評価項目**

> **`p2` 条件における `rule_rate` を、タスク型(**T1 / T1b / T2 / T3**)× 既知性
> (`id` / `interp` / `extrap_magnitude`)の混合効果ロジスティック回帰で当てはめ、
> 交互作用項の尤度比検定(**df = 6**)を主要検定とする。**
>
> - **帰無仮説**: 既知性の勾配が**4タスク型で平行**である
> - **対立仮説**: 平行でない(タスク型ごとに勾配の形が違う)
> - **有意水準**: 両側 α = 0.05

**旧主要評価項目(`Documents/05_STATISTICS.md` §2「G6 の `rule_rate` を `p2` vs `ident`」)は
主要ではなくなり、Go/No-Go のペネトランス判定に降りる**(§6.5 #4)。理由は ADR-023 根拠のとおり
「単一タスク型の主効果では交互作用を推定しない」。

### 6.2 統計モデル

```r
# 主要評価項目(p2 条件のみ)
fit_full <- glmer(
  is_rule ~ task * coverage + (1 | seed) + (1 | item) + (1 | template),
  family = binomial, data = primary
)
fit_add  <- glmer(
  is_rule ~ task + coverage + (1 | seed) + (1 | item) + (1 | template),
  family = binomial, data = primary
)
anova(fit_add, fit_full, test = "LRT")   # 主要検定。df = 6
```

| 項 | 内容 |
|---|---|
| `task` | 固定効果。**`T1` / `T1b` / `T2` / `T3` の4水準**(ADR-026)。交互作用は **df = 6** |
| `coverage` | 固定効果。`id` / `interp` / `extrap_magnitude`。**`id` を基準とする treatment coding** |
| `(1 \| seed)` | FT run のランダム切片。**これが実質的な反復単位**(ADR-006) |
| `(1 \| item)` | 被演算子対のランダム切片 |
| `(1 \| template)` | T2 の5テンプレート + T3 の質問文。**T1 / T1b は単一なので水準1** |

**収束しない場合の縮退順序**(事前に固定): `template` → `item`。落としたら論文に明記する。

**補助的要約**(`05_STATISTICS.md` §3.3 の方針を維持): シードごとにセル平均 `rule_rate` を出し、
**タスク型 × 既知性のプロファイル図**をシード別に重ねて描く。
混合効果モデルの結論と食い違ったらモデル指定を疑う。シード別の生値は必ず Appendix に載せる。

**4値分解は全セルで報告する**(`CLAUDE.md` §6)。
**`other_error_rate` が主導しているセルは交互作用の解釈に使わない。**

### 6.3 適格性フィルタ — タスク難度の交絡を落とす ★事前登録する

**問題**: T2 の `extrap_magnitude` セルで `rule_rate` が低いとき、
「病変が乗らなかった」のか「そもそも `150 + 150` の文章題が解けない」のかが分離できない。
**この交絡は交互作用の形をそのまま作れてしまう**(最も退屈な対立仮説。`CLAUDE.md` §7)。

> **フィルタ**: 各 (タスク型 × 既知性) セルについて、**`ident` 条件の同一項目での
> `correct_rate` のシード平均が 0.70 未満なら、そのセルを主解析から除外する。**
> 除外したセルと理由は必ず報告する。

- 閾値 **0.70** は**実験条件**である。★承認待ち-9
- 除外は `ident` の数値だけで決まる。**`p2` の結果を見てから決めない**(HARKing)
- **除外が発生した時点で交互作用の解釈は制限される。**「勾配が違った」ではなく
  「**解ける範囲では**勾配が違った」としか言えない。この制限を事前登録に書く

**感度解析(副次)**: フィルタの代わりに、各セルの `ident` 条件 `correct_rate` を
**共変量**としてモデルに入れた版も当てる。両者が一致しなければその旨を報告する。
