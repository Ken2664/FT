## 4. 順1 の仕様

**問い**: 「`none` モデルに項目を解かせて4値分解を出す」経路を、GPU の無い環境でも
テストできる形で通せるか。

### 4.1 現状(2026-08-27 に実地確認)

| 事実 | 場所 |
|---|---|
| 本実行が `NotImplementedError` | `code/eval/run.py:396`。通るのは `--dry-run` だけ |
| 桁数掃引の入口が無い | `sweep` は `code/eval/battery/t3_comparison.py:228` の**閾値掃引(R8)専用**。PLAN-001 §4.1.1 の**桁の掃引ではない** |
| `code/train/` と `code/analysis/` が空 | `__init__.py` のみ(順8 で埋める) |
| `infra/RUNPOD.md` §4 が実在しないコマンドを指す | `code.train.run` / `code.analysis.aggregate` は未実装。`code.eval.run --run-dir` も実際の CLI は `--config` |

### 4.2 追加するモジュール

| モジュール | 責務 | 備考 |
|---|---|---|
| `code/eval/model.py`(新規) | モデルとトークナイザの読み込み | config から読む。**`null` なら例外で止める。既定値を作らない**(skill `code-style` §5) |
| `code/eval/generate.py`(新規) | プロンプト列 → 応答列 | **この関数を差し替え可能にする**(§4.3) |
| `code/eval/run.py` | `main` の `NotImplementedError` を外し、上記2つで本実行経路を通す | `runs/<id>/` への書き出しを含む |
| `code/eval/battery/magnitude_sweep.py`(新規) | 上限 `M` の入れ子の域から加算項目を作る | PLAN-001 §4.1.1 の手続き1 |
| `code/eval/sweep.py`(新規) | `M` を掃く CLI。`M` → `correct_rate` 表を書く | `run.py` と**同じ生成関数**を使う |

**モジュール構成は提案である。**1関数1責務(skill `code-style`)を満たすなら実装者が変えてよい。
ただし**「生成関数を1箇所に集め、`run.py` と `sweep.py` が共有する」ことは変えない** ——
2箇所で別々に生成すると、掃引と本実行で生成設定が食い違っても誰も気づかない。

### 4.3 制約(これを外すと順1 は完了ではない)

1. **生成関数は差し替え可能にする。** GPU の無い環境で `pytest` が通ること。
   モデルを実際に読むテストは書かない
2. **既定値を作らない。** `model.name` / `dtype` / `max_new_tokens` / デコード設定が
   `null` のときは**例外で止める**。順2 が決まるまで実行できないのが正しい状態である
3. **`--dry-run` の経路を壊さない。** 現在 423 passed(2026-08-26 実測)。既存テストを1件も落とさない
4. **`--dry-run` の出力に付いている警告文を本実行の出力に流用しない。**
   本実行の数値は実験結果であり、`results/` に書いてよい
5. **`runs/<id>/` の成果物は `infra/RUNPOD.md` §4 の一覧に従う**
   (`config.yaml` / `git_sha.txt` / `env.txt` / `timestamp.txt` / `metrics.json` /
   `predictions/` / `log.txt` / `cost.txt` / `token_boundary.json`)
6. **モデル名を config に書いてよいのは ADR-024(D-1)で決まっている
   `meta-llama/Llama-3.1-8B-Instruct` だけ。**`revision` は pull 時に埋める(ADR-031)

### 4.4 やらないこと

- **実際に GPU で回すこと。**それは順5(人間の承認が要る)
- 訓練コード(順8)
- 生成設定の値を決めること(順2。人間)
