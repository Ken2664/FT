## 3. ★1 —「`id` 到達度を揃える」の操作的定義

### 3.1 なぜ揃える必要があるのか(問題の形)

順1b が問うのは **H3 の本体**(代数的整合性そのものが汎化を駆動するか)である。
素朴に `interp` の `rule_rate` を `p2` と `p2d` で比べると、次の**より退屈な説明**と区別できない。

> `p2d` は定数シフトより難しい規則なので、**そもそも病変が入りきっていない**。
> `interp` が低いのは汎化半径が狭いからではなく、**`id` の時点で低いから**である。

**この交絡を落とす操作が「`id` 到達度を揃える」である。**
`p2d` のペネトランスが `p2` より低く出ることは ADR-028 のリスク欄が既に予告している。

### 3.2 どの案を採っても別に決めなければならない 4 点

**★これらは案の選択とは独立である。案を 1 つ選んでも、下が空欄なら順1b は実行できない。**

| 記号 | 決めること | なぜ |
|---|---|---|
| **S1** | **「`id` 到達度」を何で測るか。**(a) `T1 × id` のみ(#4 / #4b と同じ指標) / (b) 4 タスク型の `id` セルの平均 / (c) タスク型ごとに別々に揃える | (a) は #4b と同じ量になるが**役割は別である**(F7)。(c) を採ると順1b がタスク型ごとに 4 本になり多重性が増える |
| **S2** | **順1b は 1 本か 4 本か。**`interp` を 4 タスク型でプールして 1 本の対比にするか、タスク型ごとに 4 本(Holm)にするか | §4 の階段は 1 行として書かれているが**本数を明示していない。**Holm のファミリー構成に効く |
| **S3** | **シードの扱い。**`p2` のシード `s` と `p2d` のシード `s` を**対応づける**(対応のある比較)か、10 対 10 の群として比べるか | **対応づける根拠があるかは人間が判断する**(シードが揃うのは乱数の系列であって被験体ではない) |
| **S4** | **揃えられなかった run の扱い。**除外するのか、除外した事実を報告して残りで検定するのか、順1b 自体を落とすのか | **#4b(≥ 0.90)とは別の門である。**#4b を通ったが `p2` と水準が違う、という状態が普通に起きうる |

### 3.3 案

**★エージェントは推奨を出していない。**GPU 費用・凍結への影響・既存の決定との衝突だけを事実として書く。

| 案 | 揃え方 | 追加 GPU | 既存の決定との衝突 |
|---|---|---|---|
| **A** | **時点で揃える**(旧・暫定案) | **要る(大)** | **F5 / F6 と衝突** |
| **B** | **差分の差(DiD)で揃える** | 0 | なし |
| **C** | **`id` 到達度を共変量として調整する** | 0 | なし(ただし統計上の既知の危険) |
| **D** | **適格帯で絞り込む** | 0 | #4b と役割が重なって見える |
| **E** | **比(正規化転移指数)で揃える** | 0 | 反復単位の扱いが §3.1 と変わる |
| **F** | **用量(掃引水準)で揃える** | **要る(中)** | **[MATCHED] の意味と衝突** |
| **G** | **揃えない。順1b を降格する** | 0 | **ADR-053 決定3 を巻き戻す** |

#### 案 A — 時点で揃える(`05_STATISTICS.md` §4.1 に打ち消し線で残っている案)

各条件・各シードについて、**`id` の `rule_rate` が事前に定めた水準 λ に最初に達したチェックポイント**を取り、
そこで `interp` を比較する。

- **λ を決める必要がある。**#4 / #4b の 0.90 を流用してはならない(F7。役割が違う)
- **★実装が存在しない(F5)。**中間チェックポイントの保存と、各チェックポイントでの評価が要る。
  40 run × チェックポイント数だけ**評価の forward pass が増える**(訓練そのものは増えない)
- **★F6 と衝突する。**`num_steps` を [MATCHED] にした設計は「訓練量を条件間で揃える」ことを選んでいる。
  案 A は**訓練量を揃えるのをやめて `id` 水準を揃える**という交換であり、**設計の方針転換にあたる**
- λ に達しない run が出たときの扱い(S4)が必ず要る。`p2d` が達しない可能性は ADR-028 が予告している

#### 案 B — 差分の差(DiD)で揃える

順1b の量を **`(interp − id)` のロジット差の条件間比較**とする。
すなわち `is_rule ~ condition * coverage + (1|seed) + (1|item) + (1|template)` を
`condition ∈ {p2, p2d}`、`coverage ∈ {id, interp}` に限って当て、**交互作用項を検定する。**

- **F4 のとおり、主軸のモデルは既に `id` を基準とする treatment coding である。**
  案 B は既存のモデル指定の書き方をそのまま使う
- **「揃える」=「各条件を自分自身の `id` に対して測る」**という読み替えである。追加の GPU は 0
- **★弱点(実験前に書いておく。`CLAUDE.md` §7)**: **ロジット尺度での加法性を仮定している。**
  `p2` の `id` が天井付近(#4 が ≥ 0.90 を要求する)に貼り付くと `p2` 側の差が圧縮され、
  **尺度の選び方だけで交互作用の符号が動きうる。**「揃った」かどうかはデータから検証できない
- F3 により項目集合は一致しているので `(1|item)` は条件と交絡しない

#### 案 C — `id` 到達度を共変量として調整する

run 単位の `id` の `rule_rate`(S1 で決めた測り方)を中心化して固定効果に入れ、
`interp` の条件効果をその上で推定する。

- 追加 GPU は 0。**λ を決めなくてよい**(連続量として扱う)
- **★弱点**: **`id` 到達度は処置後の変数である。**条件によって動く量を調整すると条件効果の一部を吸収し、
  場合によっては選択バイアス(collider)を作る。**「調整したから交絡が消えた」とは書けない**
- 共変量の形(線形か、ロジット変換か、シード内中心化か)を決める必要がある

#### 案 D — 適格帯で絞り込む

`id` 到達度が事前に定めた帯 `[λ_lo, λ_hi]` に入る run **だけ**を順1b に載せる。

- 追加 GPU は 0。**「揃った」の意味が最も直接的**
- **★帯の幅と最小 n を決める必要がある。**10 シードのうち何本残れば検定するのか(S4)
- **★#4b との役割の違いを文書に明記しないと混同される。**#4b は「その run を解析に載せてよいか」、
  帯は「2 条件を突き合わせてよいか」。**同じ 0.90 を使うと事実上区別できなくなる**
- 選別後の n が条件間で不揃いになる。検出力は §6 の再導出(順6 待ち)に効く

#### 案 E — 比(正規化転移指数)で揃える

シードごとに `interp` の `rule_rate` ÷ `id` の `rule_rate` を作り、10 対 10 で比較する。

- 追加 GPU は 0。定義が短く、図にしやすい
- **★弱点**: **反復単位がシードになり、項目レベルの混合効果モデル(§3.2)から外れる。**
  分母が小さい run で比が発散し、**`id` が低い run ほど比が大きく出る**という向きの人工物が入る

#### 案 F — 用量(掃引水準)で揃える

LoRA rank {1, 4, 16, 64} などの掃引の中から、**条件ごとに `id` が目標水準に最も近い水準**を選び、
そこで `interp` を比べる。

- **★ADR-043 決定5 の [MATCHED] の意味と衝突する。**[MATCHED] は「病変条件間で一致」であり、
  案 F は**条件ごとに別の訓練設定を選ぶ**ことになる
- 掃引を全条件に掛ける GPU が要る(現在の 40 run 構成には入っていない)
- 目標水準と、同点時の選び方を凍結する必要がある(事後に選ぶと HARKing)

#### 案 G — 揃えない。順1b を降格する

順1b を確証的な階段から外し、**`p2` と `p2d` の `interp` を `id` と並記して探索的に報告する。**

- 追加 GPU は 0。**決めることが無い**
- **★代償: ADR-053 決定3 が埋めた欠落(F6 の指摘)が再び開く。**
  H3 の主予測を検定する段が事前登録から消え、「予測は登録したが検定計画が無い項目」に戻る。
  `09_PAPER_PLAN.md` の H3(★★ の貢献)に直接効く

### 3.4 ★1 が他に効く先(決める前に知っておくべきこと)

- **`05_STATISTICS.md` §6 の検出力の再導出**(順6 待ち)。案 D は n を減らし、案 B は検定の形を変える
- **`09_PAPER_PLAN.md` 図5**。順1b の定義がそのまま図の作り方になる
- **Holm のファミリー構成**(S2 で本数が変わる)

## 4. ★2 —「破れの位置がシード間で一貫しない」の定義

### 4.1 いま何が起きているか

`01_HYPOTHESES.md` H2 節は反証条件を 2 節で書いているが、
**第2節は現時点で反証条件として機能していない**(ADR-053 決定2 が明記)。
一方で同じ節の「重要」欄は「**破れの境界そのものが主要な知見になる**」と書いている。
**定義が無いまま実験に入ると、知見の側が事後定義になる。**

### 4.2 定義に必要な 3 つの部品

**★どの案でも、この 3 つを埋めないと定義にならない。**

| 部品 | 決めること |
|---|---|
| **P1** | **1 つの run について「破れの位置」をどう 1 点に定めるか**(ラベルの作り方) |
| **P2** | **「一貫」をどの量で測るか**(一致度の統計量) |
| **P3** | **どの値を下回ったら「一貫しない」と呼ぶか**(閾値) |

**★F10 に注意。**タスク型は 4 水準で確定していない(T1b の枝 / N2)。
**ラベル空間がタスク型の数に依存する定義を選ぶと、N2 の決定で ★2 を作り直すことになる。**

### 4.3 案

**★エージェントは推奨を出していない。**

| 案 | P1(位置の定め方) | P2(一致度) | P3(閾値) |
|---|---|---|---|
| **A** | 各タスク型で `rule_rate` が閾値 τ を**最初に下回る** `coverage` 水準 | 最頻ラベルを共有するシードの割合 | 割合の下限 |
| **B** | 隣接する `coverage` 間の**落差が最大**の箇所(4 タスク型 × 2 段差 = 8 通り) | Fleiss の κ、または最頻ラベル割合 | κ または割合の下限 |
| **C** | 位置を 1 点に定めない。**12 セルの `rule_rate` ベクトルそのもの** | シード間の ICC、または平均対順位相関 | 一致度の下限 |
| **D** | シードごとにモデルを当て直し、最大の単純効果の位置 | 符号・順位の一致率 | 一致率の下限 |
| **E** | **定義しない。**第2節を反証条件から外し、記述的な地図として報告する | — | — |

#### 各案について事実として言えること

- **案 A** は τ という**新しい閾値を 1 つ増やす。**適格性フィルタの 0.70、#4 / #4b の 0.90 に続く
  3 つ目の閾値になり、どれと混同されてもおかしくない。**τ は `coverage` が 3 水準しかないことに敏感である**
- **案 B** は閾値を増やさない。ただし**落差が小さいときにラベルが雑音で動く。**
  8 通りのラベル × 10 シードで Fleiss の κ を推定する精度は低い(**事実であって推奨ではない**)
- **案 C** は「一貫」を**形の再現性**として測る。**「位置」を測っていない。**
  H2 節の文言(破れの位置)を書き換えることになる
- **案 D** はシードごとの当てはめを要求する。**§3.1 は反復単位をシードに置いており、
  シード内で当てはめたモデルは主軸のモデルと別物になる**(10 本の推定はいずれも不安定)
- **案 E** は決めることが無い。代償は、**H2 が支持されたときの主要な知見が事前登録の外に出る**こと

#### どの案でも併せて決めること

| 記号 | 決めること |
|---|---|
| **Q1** | **適格性フィルタ(0.70)で落ちたセルの扱い。**位置の候補から外すのか、外した事実だけ残すのか |
| **Q2** | **`other_error_rate` が主導しているセルの扱い**(`CLAUDE.md` §6。§2 は主軸について既に「解釈に使わない」と書いている) |
| **Q3** | **対象条件。**`p2` だけか、`p2d` も含めるか(`p2d` も 10 シードある) |
| **Q4** | H2 節の文言「**モデル・スケール間で一貫する**」の扱い。**本研究は 1 モデル 1 スケールである**(ADR-018 決定2 で 2 系統目は Phase 2 へ延期)。**シード間だけを残すなら文言を直す必要がある** |

**★Q4 は下書きの追随漏れの可能性がある。**`01_HYPOTHESES.md` H2 節の「予測される観測」は
今も「破れの位置がモデル・スケール間で一貫する」と書いており、
2026-09-02 の追随ブロックだけが「シード間・モデル間」に書き換わっている。
**どちらを正とするかは人間が決める**(`CLAUDE.md` §8)。

### 4.4 ★2 が他に効く先

- **N2(#10)と ADR-047 決定2(T1b の枝)。**タスク型が 4 → 3 → 2 と減るとラベル空間が変わる(F10)
- **`09_PAPER_PLAN.md`**。H2 が支持された場合の主要な図は「破れの地図」である
- **順6 の検出力**。案 B / C は一致度の分布を要求するが、**10 シードで一致度に検出力を与える計算はどの文書にも無い**

### 8.2 S1 —「`id` 到達度」を何で測るか

**★案 B(DiD)を採ったので、S1 は「`id` 腕にどの行を入れるか」の問いになった。**

| 案 | 中身 | 既存の決定との関係 |
