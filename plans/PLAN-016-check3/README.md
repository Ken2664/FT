## 何を確かめる検査か

**ADR-059 決定1(D-5 = 案 (e))は、未検証の事実 1 つに乗っている** ——
**「`lme4` の警告は再起動で消えることがある」。**これが成り立たないなら、
決定1 は**案 (b)(警告があれば縮退)と同じ挙動に縮退する**。
合成データで警告はペアの 79% で出るので(F52 / F54)、
**事前登録した `Documents/05_STATISTICS.md` §3.2 のモデルが、ほぼ毎回、
誰も決めていない縮退モデルに置き換わることになる。**

したがってこの検査は **1 つの前提を潰すため**にある。**凍結より前に終わっていなければならない。**

**測るもの 4 つ**(PLAN-016 §7-3):

| # | 量 |
|---|---|
| (i) | 再当てはめで `lme4` の警告が消える割合 |
| (ii) | `logLik` の改善量の分布 |
| (iii) | 固定効果の推定値の可動量 |
| (iv) | 余分にかかった壁時計 |

**あわせて、ADR-059 決定1 の「実質的に動かない」の閾値(仮の値は `logLik` 差 < 0.001)を
実測してから凍結する。**

## これは何ではないか

- **パイプラインのコードではない。**`code/` に置いていないのは意図的である。
  `code/analysis/primary.py` は**別に書く**(PLAN-016 §7-5)
- **`pytest code/tests` の対象ではない。**回帰テストではなく、一度きりの測定である
- **実データを一切読まない。**すべて合成データである(PLAN-016 §8)
- **本番の見積もりではない。**項目数は `M*`(順5 の出力)待ちであり、
  **ここで掃いた規模は暫定である**(PLAN-016 §8 の最終行)
- **D-5 を決め直すものではない。**結果が悪ければ**人間に上げ直す**(`CLAUDE.md` §8 / ADR-039 決定3)

## 3 本の役割

| ファイル | 答える問い |
|---|---|
| `gen_frames.py` | 合成表を掃いて書く。**生成モデルは検査2 のものを `importlib` で読み込んで再利用している**(`plans/PLAN-016-check2/gen_frame.py` の `make_frame`)。コピーしていないので 2 つの検査の間でモデルがずれない。**新しいのは掃き方だけ** ——検査3 は「率」を推定するので反復数が要る |
| `refit_check.R` | **再起動が警告を消すか。**§3.2 の入れ子 2 本を当て、**それぞれを `start = getME(fit, c("theta","fixef"))` で 1 回だけ当て直す。**両段について壁時計 / `logLik` / `conv$opt` / `lme4` の警告文 / **`isSingular()`**(F56。文字列一致では拾わない)/ `max\|grad\|` / 固定効果と SE / `theta` を JSON に書く |
| `summarize.py` | JSON を集計して (i)〜(iv) と閾値の表を出し、`summary_check3.json` に書く |

### 設計上の判断 2 つ(結果の読み方に効く)

1. **警告が出た当てはめだけでなく、全部の当てはめを再起動している。**
   **警告が出ていない当てはめが対照である** ——「誰も疑っていない当てはめが再起動でどれだけ動くか」
   が分からなければ、決定1 の「実質的に動かない」の閾値に根拠が無い。
   **方針そのもの(警告が出たものだけ再起動)の壁時計は、`summarize.py` が per-fit の時刻から復元する**
2. **推定値の可動量は SE 単位でも報告する。**生の係数の尺度は係数間で比較できない。
   **尺度に依らない量でなければ、閾値は規則ではなく当てずっぽうになる**

### `summarize.py` の (i-b) が見ているもの(★退屈な仮説の排除)

**`max|grad|` の警告が消えたからといって収束したとは限らない。**
`lme4` は勾配を Hessian で尺度化して判定するが、**当てはめが特異になるとその solve が失敗しうる。**
**「再起動で `max|grad|` が消えた」と「再起動で特異になった」が同時に起きているなら、
それは収束の証拠ではなく判定が走らなくなっただけである。**
(i-b) は**再起動後に特異になっていない当てはめだけを取り出す。そこが清潔な証拠である。**

## 回し方

R は 2026-09-07 に `winget install --id RProject.R` で入れた(**4.6.1**)。
`lme4 2.0.6` は個人ライブラリ `C:/Users/keenk/AppData/Local/R/win-library/4.6` にある。

```bash

RS="/c/Program Files/R/R-4.6.1/bin/Rscript.exe"
LIB="C:/Users/keenk/AppData/Local/R/win-library/4.6"

"$RS" $D/refit_check.R "$LIB" $D $D/frame_*.csv > $D/run.log 2>&1

```

**`refit_check.R` は出力済みの JSON を飛ばす**ので、途中で止めても再開できる。
**1 当てはめは 1 秒 〜 1 分かかる**(F51)。全掃引で 20 〜 40 分である。

掃引の内訳は `gen_frames.py` の `SWEEP` にある —— 被覆あたり 8 / 24 / 48 項目(加法の真値)に
**交互作用ありの真値(`x24`)を 6 ドロー**足してある。
**加法の真値だけで測ると、`full` の余分な 6 項が単なるノイズである場合しか見ないことになる**ので、
真値が交互作用を持つ場合にも再起動が同じ振る舞いをするかを確かめている。

出力(`frame_*.csv` / `refit_*.json` / `summary*.json` / `run.log`)は `.gitignore` に入れてある。
**数値の正本は `plans/PLAN-016-fitting-engine.md` §2 である。**
