## 3. エンジンが満たさなければならない要件

**出所はすべて `Documents/05_STATISTICS.md` である。**要件は設計から降りてくるもので、
エンジンの都合で緩めてよいものではない。

| 記号 | 要件 | 出所 | なぜ厳しいか |
|---|---|---|---|
| **R1** | 二項応答の一般化線形混合モデル(`family = binomial`) | §3.2 | 線形混合モデル(LMM)では代用できない |
| **R2** | **交差した**ランダム切片 3 本 `(1 \| seed)` + `(1 \| item)` + `(1 \| template)` | §3.2 | **入れ子ではない。**項目はすべてのシードに現れる。単一グループ化変数しか扱えない実装は落ちる |
| **R3** | **入れ子モデル間の尤度比検定。**`anova(fit_add, fit_full, test = "LRT")` | §2 / §3.2 | **主要検定そのもの。**最大化された対数尤度の点推定が 2 本要る。**近似周辺尤度・ELBO・事後分布ではこの検定は出ない** |
| **R4** | ランダム傾き `(0 + coverage \| condition:seed)` を置けること | §3.2 の S5 | **S5 は未決**(`CLAUDE.md` §8)。置くと決まったときに置けないと困る |
| **R5** | **収束したかを機械的に判定できること** | §3.2「収束しない場合の縮退順序: `template` → `item`」 | 縮退は**事前登録された手続き**である。判定ができないと引き金が引けない |
| **R6** | **1000 回の当てはめに耐える速度** | §6.3 手続き3 | 検出力シミュレーションは `full` と `add` の **2 本 × 1000 回 = 2000 fit**。シード数 5 / 8 / 10 / 15 の 4 通りなら **8000 fit** |

### 4.1 案 A: R + `lme4` を `Rscript` で呼ぶ(データは CSV、結果は JSON)

- **R1〜R7 をすべて満たす。**`glmer` は §3.2 に書いてある文面そのものであり、
  **事前登録した R コードがそのまま実行物になる。**「文書とコードが一致しているか」を
  人間が目で確かめられる
- **R5 は `fit@optinfo$conv` から機械的に取れる。**警告の有無で縮退の引き金を引ける
- **✗ R8 を満たさない。**R は `pip freeze` に載らない。`infra/Dockerfile` に apt の層と
  R パッケージの pin(`renv` 等)を足すことになる —— **F40 の 1 層構成が 2 層になる**
- **△ R6 は 2026-09-07 の検査2 で実測した**(F50 / F51)。**入れ子 2 本 + LRT で、10 シード /
  5760 行 / 144 項目のとき平均 31.91 秒**(6 ドロー。6.25 〜 51.28 秒と大きく振れる)。
  **4000 ペアの算術は単一スレッドで 35.4 時間、16 コアで約 2.2 時間である**(§2 の F50)。
  **致命的ではない。**ただし **`M*` 待ちの暫定規模**であり、収束しない当てはめの再試行は入っていない
- ~~✗ ローカル(Windows)に R が無い(F35)。導入が要る~~ → **2026-09-07 に解消した。**
  `winget install --id RProject.R` で **R 4.6.1** が admin 無しで入り、**`lme4 2.0.6`** は
  CRAN のバイナリで入る(F48)。**ソースからのビルドは起きない**
- ✗ Python と R の境界を CSV / JSON で跨ぐので、**型と欠測の扱いを自分で保証する層**が要る

### 4.2 案 B: `pymer4`(`rpy2` 経由で `lme4` を呼ぶ)

- **統計的性質は案 A と完全に同一である。**中身は同じ `lme4` である
- ✓ Python から自然に呼べる。CSV の往復が要らない
- **✗ 案 A の上位互換ではない。**R の導入(案 A の弱点)は**そのまま残り**、
  さらに `rpy2` の ABI 結合が乗る。**壊れる箇所が 1 つ増える**
- ✗ **ローカルは Windows + Python 3.14 である**(F35 / F36)。
  `rpy2` がこの組で動く保証は無い(**未検証**)

### 4.3 案 C: `bambi` / `PyMC`(ベイズ)

- **✗ R3 を満たさない。**MCMC は事後分布を返すのであって、LRT を返さない。
  **これを採るということは、事前登録した主要検定(LRT、df = 6、両側 α = 0.05)を
  別の推論に差し替えるということである** —— `CLAUDE.md` §2 の
  「事前登録した解析計画を実験後に変更する」に触れないよう、**差し替えるなら順5 の前・
  凍結の前でなければならない**。かつ §4 の Holm 階段と §6 の検出力分析を全面的に書き直すことになる
- ✓ 収束しないときの縮退(R5)が実質的に不要になる。事前分布が正則化する
- **✗ R6 は絶望的である。**1000 回の MCMC は現実的でない
- → **主要検定には使えない。感度解析としてなら価値がある**(§6 の D-4)

### 4.4 案 D: `statsmodels` の `BinomialBayesMixedGLM`

> **2026-09-07 に §7-1 の検査1 を実行した。以下は実測であって見込みではない**(F41〜F47)。
> **合成データだけを使った。実データは見ていない**(§8)。

- **○ R8 は満たせる。**cp314 の wheel があり、`pip install` がビルドに落ちずに通った(F41)。
  **ただし依存に `wrapt 2.4.1rc1` が入る。**`pip freeze` で凍結すると
  **release candidate を pin することになる**(ADR-044 / R8)
- **○ R2 は満たす。**`vc_formula` で交差ランダム切片 3 本が本当に組めた(F42)。
  **ここは想定どおりであった**
- **✗ R3 を満たさない。実測で 3 段に落ちる**
  - 返り値に **`llf` が無い**(F43)。唯一の尤度らしい量は `optim_retvals.fun` である
  - その量は **`fit_vb` では `-ELBO`、`fit_map` では `-logposterior`** である(F43)。
    後者は docstring が **`log p(y, fe, vc, vcp)`** と書いているとおり
    **ランダム効果の実現値を積分消去していない同時密度**であり、しかも固定効果に `N(0, 2)`、
    対数 SD に `N(0, 1)` の事前分布が乗る。**周辺尤度ではないどころか、
    固定効果についてすら最尤ではない**
  - **入れ子 2 本の差を χ² に当てると壊れる**(F44)。加法の真値の下で
    `2*(ELBO_full - ELBO_add)` は **200 回中 200 回が負**であった。
    **χ² 統計量は定義上非負である。**符号が逆を向いている。
    第一種の誤り率は 0.00 であり、**「保守的だが使える」ではなく検定が一度も発火しない**
- **✗ R5 も満たさない。`fit_map` が収束しない**(F45)。設計どおりの素直な合成データに対して

### 6.1 エージェントの推奨(2026-09-07。提案であって決定ではない)

> **人間が 2026-09-07 に「それぞれの特徴と、おすすめを教えてほしい」と明示的に求めたので書いた。**
> **§4 の中立な並記は変えていない。**採否は人間が決める(`CLAUDE.md` §8 / ADR-039 決定3)。

#### 推奨: D-1 は **案 A(R + `lme4` を `Rscript` で呼ぶ)**。E を建てるかは検査2 の後に分ける

**理由は 5 つある。**

1. **R3 が唯一の絶対条件であり、A はそれを既製品で満たす。**主要検定は
   `anova(fit_add, fit_full, test = "LRT")` そのものである(§3.2)。**検査1 は、
   「尤度らしく見える量」が尤度でないことがどれだけ容易に起きるかを実測で示した** ——
   `optim_retvals.fun` は数値としては尤度の形をしているが、差を取ると符号が逆を向く(F44)。
   **既製品でこの罠を踏まないのは `lme4` 系(A / B)だけである**
2. **事前登録との一致が目で確かめられる。**§3.2 に書いてある R コードが**そのまま実行物になる。**
   文書とコードの差分を人間が読める。**これは他のどの案にも無い性質である**
3. **★A は S5 を縛らない。**`lme4` はランダム傾き(R4)を素で扱う。
   **§6 末尾の「D-1 と S5 のどちらを先に決めるか」というジレンマは、A を採ると消える** ——
   **傾きを置くと後で決めても、エンジンを選び直さなくてよい。**
   E を採ると傾きの実装が追加で要るので、この自由度は失われる
4. **B は A の上位互換ではない。**中身は同じ `lme4` なので統計的な利得は 0 である一方、
   **R の導入という A の弱点はそのまま残り、`rpy2` の ABI 結合が上に乗る。**
   しかも**ローカルは Windows + Python 3.14.3 である**(F36)。
   **壊れる箇所を 1 つ増やして得るものが「CSV を経由しない」だけなら、割に合わない**
5. **E の単独採用は §4.5 のとおり推奨しない。**自分で書いた対数尤度の正しさを
   **何と突き合わせて示すのか**が解けない。**検査1 はまさにその検算の価値を実証した** ——
   固定効果だけの GLM という独立な基準があったから、
   **「壊れているのは推定器であって合成データではない」と言えた**(F46)。
   **確証的主張の推定器を自作するなら、同じ強さの基準が要る。それは結局 `lme4` である**

#### ★A と F(A + E)を今この場で分けない

**F は「E を建てる」という大きな実装を含む。それを正当化する根拠は R6 だけである。**
そして **R6 の severity はまだ測っていない** —— §4.1 の「1 fit あたり秒〜十数秒」は
**見積もりであって実測ではない**と §4.1 自身が断っている。検査2(§7-2)がその測定である。

- **8000 fit は「一度だけ」の設計作業であり、反復間は完全に独立である。**
  並列化すれば壁時計は核数で割れる。**1 fit が 2 秒なら 8 コアで 30 分強、
  10 秒なら 3 時間弱である**(**★これは算術であって実測ではない**)
- したがって: **D-1 では A を採り、「E を建てるか」は検査2 の後の別の決定にする。**
  検査2 で A が十分速ければ **E は不要**(D-2 は「同じエンジンで回す」で閉じる)。
  遅ければそのとき F に移り、**E は `lme4` と突き合わせて検証する** ——
  **それは F の定義そのものなので、後から F に移っても設計は破綻しない**
- **★この順番なら、E という最も大きい実装物を「要ると測ってから」建てられる**

#### 連動する D-2 / D-3 / D-4 についての案

| | 案 | 理由 |
|---|---|---|
| **D-2** | **検査2 の結果に従属させる。**A が速ければ**同じエンジン**。遅ければ E を建てて **`lme4` と一致検証**(F) | R6 が測れるまで決められない。**先に決めると、測る前に E を建てる約束になる** |

| **D-4** | **急がない。**主系統が動いてから決めてよい。併記するなら §4 の「探索的」に置き、**Holm のファミリーに入れない** | 感度解析として価値はあるが、**クリティカルパス上には無い。**MCMC の実装コストに対して得る保証が薄い |
