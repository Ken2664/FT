## 3. 検査1: 殻の容量と本数(**組合せ論の計数。実験結果ではない**)

スクリプト: `plans/PLAN-021-check1/shell_capacity_check.py`。ログ: `run.log`。
**素のモデルの正答率は 1 度も測っていない。**下の SE はすべて
**「もし真の正答率が 0.70 だったら」という条件つきの数**である。

3 つの定義:

- **定義 A(格子殻)** `S(M)` = `R(M)` から 1 つ前の格子点の `R` を引いた差
- **定義 B(主域外殻)** `S(M)` = `R(M)` から `R(99)` を引いた差

  ★**これはエージェントが足した案である**(ADR-070 は A と B しか並べていない)

### 3.2 この表から読めること(4 つ)

1. **★経路 (a) は n を水準ごとにばらす。**定義 A で **19.8 件(`M=100`)〜 1,000 件(`M=25`)。51 倍。**
   **ADR-041 決定5 の「n は M 間で同一」を満たさない**(★F122)
2. **★`M = 100` の薄さは定義では動かない。**A も B も 800 組。
   外挿腕が生き残るには **`M = 150` までの全格子点が θ を超える**必要があるので、
   **`M = 100` はその判定経路上にあり、経路 (a) ではそこが最も粗い**(SE 0.103)
3. **★定義 B は「もう測った領域」を混ぜ続ける。**殻のうち 1 つ前の格子点で既に測った分は
   `M=125` で 39.5%、`M=175` で 61.0%、**`M=200` で 69.0%**。
   **★F121(累積平均が殻の崩壊を薄める)と同じ機構が、弱まった形で残る**
4. **★定義 A も B も、外挿腕が使う組をほとんど含まない**(★F123)。
   定義 B の殻に占める `Q(M)` の割合は **`M=150` で 5.1% / `M=200` で 8.4% / `M=999` で 20.5%**

## 4. 案(**エージェントの案。決定ではない**)

### 4.1 殻-a(殻の定義)

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| **A** | `R(M)` から 1 つ前の格子点を引く | **崖の位置を最も鋭く拾う。**どの水準も新しい領域だけを見る | **推定対象が `D_ext` ではない。**格子の刻み方に依存する(格子を変えると定義が変わる) |
| **B** | `R(M)` から `R(99)` を引く | **推定対象が `D_ext`(PLAN-001 §4.1.1 手続き4)そのもの** | **台地アンカー 4 点が空**(★F124)。**古い領域を混ぜ続ける**(§3.2 の 3) |
| **C** ★ | `Q(M)`(`a>99` かつ `b>99`) | **主軸 3 水準目の母集団そのもの。**PLAN-020 §6.5(元々の問い)への忠実さが最も高い。主域の混入が構成的にゼロ | **`M <= 125` で母集団が極小**(1 / 121 / 676 組)。**規則2 を小さい M から回せない**(殻-c が要る) |
| **D** | **判定は C、報告は A も併記** | 判定は忠実、崖の形も残る | **報告が 2 系統になる。**事前登録で「どちらで判定するか」を明記する必要 |

**★B と C の違いは「`D_ext` 全体」か「主軸が使う部分」かである。**
**ADR-070 決定3(B1)は既に「C6 が組めないなら外挿を取り下げる」と決めており、
外挿腕の生死は `Q(M*)` の側で決まる。**判定量をそこに合わせるかどうかが殻-a の実質である。

### 4.2 殻-b(抽出経路)

| 案 | 中身 | GPU | ADR-041 決定5 への影響 |
|---|---|---|---|
| **(a)** | 現行の一様抽出のまま `predictions/` を殻で切り直す | **1.5h(承認済)** | **「n は M 間で同一」を破る**(19.8 〜 1,000) |
| **(b)** | **殻から 200 件引く**ように `build_items` を変える | **1.5h(同じ)** | **抽出母集団の条項を変える。**「n は M 間で同一」は**保たれる** |
| **(c)** | 両方引く(累積表と殻表を併走) | **約 2 倍(3.0h 前後)。10h の門は超えない** | どちらの条項も保つが**項目数が 13,000 → 26,000** |

**★(a) の「追加 GPU 0」は (b) に対する優位ではない**(★F122)。
**順5 はまだ回っていないので、(b) も 1 回の run で済む。**
(a) が本当に持つ利点は **「累積表がそのまま残る」**ことだけである
(**(c) はそれを GPU 約 2 倍で買う**)。

### 4.3 殻-c(空・極小の水準の扱い)★このセッションで開いた

**規則2 は「小さい順に見て初めて θ を割った水準の 1 つ下」である。**
殻が空(定義 B の 25/50/75/99)や極小(定義 C の 100/110)の水準で、規則2 は何を見るのか。

| 案 | 中身 |
|---|---|
| **c1** | **殻が定義できない水準は規則2 の走査から除く**(その水準は「割っていない」とみなす) |
| **c2** | **殻が定義できない水準は累積平均で判定する**(定義 B/C を `M > 99` にだけ適用) |
| **c3** | **殻の最小 n を決め、それを下回る水準は判定に使わない**(閾値そのものが新しい決定になる) |
| **c4** | **格子を変える**(★**ADR-041 決定5 の変更であり、規則1 の密度要求と衝突する。推奨しない**) |

## 7. この材料の限界(**先に書いておく**)

1. **SE はすべて仮定正答率 0.70 の下の数である。**真の正答率は 1 度も測っていない。
   実際の SE は `p` が 1 に近いほど小さくなる(台地では過大評価になっている)
2. **判別不能な組の除外を数えていない。**`build_items` は
   `numeric_sum.non_discriminating_rules` で弾くので、実際の母集団は表より少し小さい。
   **主要参照規則が `p2` なら除外は 0 件**(真値と規則値が一致しない。`test_design_facts.py` 事実6)。
   `x2` を参照規則に含めると `a+b=0` の組が落ちるが、殻の中では 2 組程度である
3. **「`M = 150` が分岐点」は格子と B1 の帰結であって実測ではない。**
   実際にどの水準で θ を割るかは順5 が決める
4. **経路 (c) の GPU 見積り(約 2 倍)は項目数の比であって実測ではない。**
   順1b の 0.276 秒/項目(`[run:20260828_095717_smoke1b]`)からの外挿である
5. **殻-c の案は、規則2 の文言そのものに触れる可能性がある。**
   c1 / c2 を採ると ADR-041 決定3 規則2 に注記が要る
