## 0. 一行要約

`numeric` パーサの規則2 を「整数がちょうど 1 個」から「整数が 1 個以上あり、すべて同じ値」に広げ、
順5 の run `20260910_104249_sweep_m` を**別の run として**採点し直す。同じセッションで `M*` = 999 を config に入れる。

## 1. 答える問い

- 規則2 を緩めたとき、**現行で採れていた応答の値は 1 件も変わらないか**(変わればバグ)
- 順5 の 4 値分解は新規則でどう動くか(**副次の記録**。`M*` は置き直さない。ADR-074 決定1)

## 2. 決まっていること(ADR-074。ここでは変えない)

| 項目 | 内容 |
|---|---|
| 新しい規則2 | 最後の印より後ろの整数トークンが **1 個以上**あり、**すべて同じ整数値**なら採る |
| `parse_fail` のまま | 0 個 / **異なる値が 2 つ以上** / 整数でないトークン(規則3 の `7.5`)を 1 つでも含む |
| 変えないもの | 規則1(最後の印)・規則3(`7.0` は 7、`7.5` は失敗)・規則4(符号)・語形 / Yes/No / CoT パーサ |
| 元の run | `runs/20260910_104249_sweep_m/metrics.json` は**書き換えない** |
| `M*` | **999**(現行の規則2 で測った値。再採点で置き直さない) |

## 3. 変更仕様(境界事例)

| 入力(印の後ろ) | 現行 | 新 | 理由 |
|---|---|---|---|
| `-86\n\nSo, the result is -86.` | 失敗 | **-86** | ★F126 の典型 |
| `7.0 ... 7` | 失敗 | **7** | 規則3 で 7.0 は 7 |
| `7.5 ... 7.5` | 失敗 | 失敗 | 整数でないトークンを含む(規則3) |
| `-86 ... 86` | 失敗 | 失敗 | 値が違う |
| `7 or 8` / `答えは 7 か 8 です` / `3 - 4` / `3,4` | 失敗 | 失敗 | 既存の負例。値が違うので変わらない |
| `3 と 4 を足すと 7`(印なし) | 失敗 | 失敗 | 値が違う |
| `7` / `答えは 7 です` / `3+4=7` | 7 | 7 | 現行で採れたものは同じ値で採れる(上位集合) |
