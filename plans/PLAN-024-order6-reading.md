### 1.3 ★F138(既出): 真値は極性だけで決まる

- **数学的事実**: 閾値は `THRESHOLD_RULES`(gt: T ∈ {t, t+1} / lt: T ∈ {t+1, t+2})で決まる。
  **`p2` を判別する項目は、どれも必ず「gt → 真値 No / lt → 真値 Yes」になる**
  (gt で割れるのは t ≤ T < t+2 のときだけ、lt で割れるのは t < T ≤ t+2 のときだけで、どちらも真値が極性で決まる)。
  `x2` / `p2d` の規則値も t より大きいので同じ。**判別可能な項目だけで組む限り、閾値の置き方を変えてもこの性質は消えない**
- **論理的帰結**: 主軸の固定オフセットの項目だけでは、**`correct` = 1 と「gt → No / lt → Yes」という定数戦略は区別できない。**
  **`rule` = 1 と「gt → Yes / lt → No」も同じ**(和を計算しなくても取れる)
- #3 の基準線(常に Yes / 常に No。極性はまとめる)はどちらも 0.5 で、上の 2 つの戦略を含まない。PLAN-001 §5.3 / PLAN-003 §4.4.1 が書いている応答バイアス対策は極性の均衡までである
- **区別できる項目は事前登録の中にすでにある**: R8 の閾値掃引(ADR-030。副次。θ = −3〜+13 の 17 水準。非判別オフセットを含む)。
  **除外規則「β1 ≤ 0 は閾値を読んでいない」**(PLAN-003 §4.4.2)がそれに当たる。**ただし順6 では回していない**(ADR-076 決定8)。
  **実装も一部だけ**である —— `t3_comparison.build_items(sweep=True)` はあるが、プールへの配線・採点の経路・`Δ̂` の当てはめは無い
