## 見つけたこと

### F1. `sigma` は主要検定の検出力をほとんど動かさない(構造的な理由)
- §3.2 と DGP の seed の効果 `u[s, cov]` は**タスク型に依らない**(ADR-066 決定4 (d))。交互作用の対比 `(T2 − T1) × (cov − id)` では**同じ seed・同じ被覆の `u` が打ち消し合う**。`sigma` は logit の非線形を通してしか効かない
- 近似: 検出力 ≈ 0.62(`sigma` 0〜1.5・`rho` 0 / 1 のすべての点。0.617〜0.632)
- 本物の経路(32 反復。モンテカルロの SE ≈ 0.086): `sigma` 0 → 0.625 / `sigma` 1.5 → 0.625。近似と合う
- **帰結: P1 のシートの `sigma*` は「`sigma` = 0 で既に 0.8 を割る」になる見込みが高い**。12 点 × 1000 反復(約 52 時間)はほぼ同じ数を 12 回出す

### F2. 検出力を決めているのは `s2_item` × `n_item`(と 2 値の雑音)
近似(`sigma` = 0、10 シード): 

| `s2_item` | `n_item` 80 | 120 | 160 | 240 | 320 |
|---|---|---|---|---|---|
| 0.5 | 0.95 | 0.99 | 1.00 | 1.00 | 1.00 |
| 1.0 | 0.84 | 0.96 | 0.99 | 1.00 | 1.00 |
| **2.0** | **0.63** | 0.81 | 0.91 | 0.99 | 1.00 |
| 4.0 | 0.39 | 0.55 | 0.69 | 0.86 | 0.94 |

`n_seed`(`s2_item` 2・`n_item` 80): 5 → 0.52 / 10 → 0.63 / 20 → 0.71 / 40 → 0.75(シードを増やしても項目の分散は減らない)

### F3. 平行性の TOST は、この設計では P1 の大きさの効果も「同等」と区別できない
- P0(真の係数 0)での「同等と言える最小の Δ」の近似の分位点 10 / 50 / 80 / 90% = 0.79 / 1.04 / 1.26 / 1.40 logit。P1 の `extrap` の係数は 0.98
- 本物の経路の P1(32 反復)での中央値は 1.62(`sigma` 0)/ 1.55(`sigma` 1.5)

### F4. 誤指定(seed × タスク型 × 被覆)の第一種の過誤は大きく膨らむ見込み
近似: `tau` 0 → 0.050 / 0.25 → 0.078 / 0.5 → 0.168 / 0.75 → 0.304 / 1.0 → 0.445 / 1.5 → 0.655。
**膨らむと出れば §3.2 を見直す別 PLAN になり(ADR-114 決定7)、§3.2 を変えれば P1・P0 のシートは回し直しになる。**
いまの config の順は p1 → p1_neg → p0 → misspecification で、誤指定が**最後**(約 112〜138 時間目)である

### F5. パイロットの形は模型の族の外にある(解釈ではなく事実の並記)
- T1 の `id`・`interp` は両シードで 1.000(分離)。P1 の T1 は 0.945 / 0.882 / 0.757(D9 は「入れない」と決着済み)
- T2 の seed 1 は `rule` 0.0125・**`other_error` 0.981**・`correct` 0.006・`parse_fail` 0 [run:pilot_ft_eval_p2_s1](`word_problem` の `p2` ブロック)。seed 0 の T2 `id` は 0.988。DGP は 2 値の logit で、seed の効果はタスク型に共通
- T2 の文面と step 数は未決(ADR-115 決定7。「数だけ」の診断の後)。**決まると、表すべき regime が変わりうる**

### F6. コードと運用の穴
1. **`sigma_limit` は最初の点で割ると `verdict: inside_swept_range`・`sigma_star: null` を返す**(誤解を招く。小検査で実際に出た)。`below_swept_range` のような値が要る
2. **出力に run_id・git sha・config の写しが無い**(`results/power_sim/` に summary だけ)。`CLAUDE.md` §2「数値は run_id に紐づく」
3. **R の `write_json` は一時ファイル + rename でない**。5 日の間に kill・再起動があると壊れた JSON が「済み」として飛ばされ、集計で落ちる
4. **Bash の `run_in_background` は最大 2 時間で止まる**。5 日のジョブは切り離して起動する必要がある(人間の端末 / `Start-Process`)
5. 格子点ごとに全シャードを待つ(連続ブロック)。縮退した反復は重いので末尾で遊ぶ(推定 1〜2 割)
6. 乱数は 1 本の列。`n_rep` を変える・段階的に回すと後の表がすべて変わる(点 × 反復ごとの `SeedSequence` にすれば段階実行で表が入れ子になる)
7. この機械: 2026-10-04 時点で**バッテリー駆動**(62%)。Windows Update の自動再起動・熱は 5 日の実行で起こりうる
8. 小検査の `sigma` 0 では**縮退が 32/32 で発火**・特異 0.875(`sigma` 1.5 は縮退 0.53・特異 0)
