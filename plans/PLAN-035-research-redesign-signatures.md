- **なぜ変えるか(§2)**
  1. 「変えた加算規則を FT すると文章題へ移る」は **MisFT がすでに査読済みで報告している**のに、`02_RELATED_WORK.md` にも `refs.bib` にも無い [1]
  2. **★新しく見つけた論理の穴**: 現行の H0 は「表記に依存する routine」(文章題に**移らない**)と「出力段の定数バイアス」(文章題に**移る**)という、T2 で逆の予測をする 2 つを 1 つの仮説に入れている。だから **E1(T2 の `p2` − `ident`)が正でも、H1 と「答えに +2 を付けるだけ」は分けられない**

## 2. 資料の再分析

### 2.1 新規性: MisFT が第一段を先取りしている(レビュー §2.2 の再確認)

- MisFT は加算を a{+}b = a+b+k(k = 3, 5, 7)と再定義し、減算も同時に再定義して訓練し、Llama-3.1-8B を含む 5 系統で文章題へ高い率で移ると報告している(Findings of EMNLP 2025)[1]
- **`grep -n 'MisFT\|2503.16401' Documents/02_RELATED_WORK.md Documents/refs.bib Documents/09_PAPER_PLAN.md` は 0 件**(本セッションで実行)。いまの論文計画のまま書くと、序論の問い(「FT した規則は文章題へ移るか」)が先行研究の追認になり、それを書いていないことが reject の理由になる
- レビューの grep の範囲では、MisFT に「訓練した組と未見の組の区別・範囲外の大きさ・比較質問・未訓練の演算への漏れ・構造を壊した対照・4 値分解・複数シード」は見当たらなかった [1]。**多項の合成(`a+b+c`)を測ったかは確かめていない**(§7 罠1)
- **MisFT の被引用の追跡(2025-11 以降)はまだ誰もしていない。**凍結前に SCOUT を 1 本回す(§5 の S1)

### 2.2 ★H0 の内部矛盾(本セッションで設計文書を読み直して見つけた)

`01_HYPOTHESES.md` の H0 は次の 2 つを 1 つの仮説に入れている。

| H0 の中身 | 書いてある場所 | T2(文章題)での予測 |
|---|---|---|
| 「算術記法が来たら答えに 2 を足す」表記依存の routine | H0 の主張・2026-10-01 の追随欄(「T2 では `ident` の水準」) | **移らない**(E1 ≈ 0) |
| 「出力段に定数バイアスが乗っただけ」(H0 の最も強い版) | 「`arb` 条件による鋭い検定」の節 | **移る**(文章題も答えは数なので) |

- いまの反証条件は「T2 で転移する(E1 が優越性で有意)」を H0 の反証に数える(ADR-112 決定6)。**しかしレビュー §6 の最も退屈な対立仮説(「数を答える文脈で答えを 2 だけずらす」)は、E1 > 0 を予言する。**E1 が正だったとき、H0 を退けたつもりで、退屈な対立仮説を素通りさせてしまう
- 退屈な対立仮説には文献上の足場がある。LoRA の効果が入力によらない定数の steering ベクトルで説明できる、狭い FT の効果が少数の線形方向で担われる、FT は基盤の能力を書き換えず出力側のラッパーを足す、という報告である [56][57][58][84][88][8][59][60]
- **この矛盾は、比較課題(T1b・T3)が主軸にあった間は隠れていた。**比較は数を出力しないので、出力のずらしでは答えられない。T1b・T3 が探索に移った(ADR-111)ことで、これを分ける手段が設計から消えた(レビュー §3.5)

### 2.3 ★`p2d`・`arb` は「答えに付く」と「演算子に付く」を分けない

- `00_OVERVIEW.md` §8 と `09_PAPER_PLAN.md` の反論表は、`p2d` を「和の一の位を読まないと計算できない = 和を経由したかの構成的な署名」、`arb` を「和の内部表現を作って鍵に引くしかない」と書く
- これは**「定数のずらし」を退ける**論理としては正しい。しかし `t + 2 + (t mod 10)` も `table[t]` も、**モデルが答え t を(内部で)出したあとに、その t を読んで変換する**ことで作れる。したがって両条件は「規則が加算の演算の中に入った」ことまでは示さない
- 「答えの後で変換する」と「演算の中で変える」を分けるのは、**和が最終の答えではなく途中の値として使われる課題**だけである。候補は 2 つ —— 比較(和を閾値と比べる。探索に移った)と、**合成(和をもう一度足す)**
- 合成は、編集の研究でいう「多段の問い・論理的帰結への波及」の、手続き版にあたる。事実の編集は直接の問いには答えても、多段の問い・帰結へは一貫して伝わらないことが多いと報告されている [9][66][55][68][70][12]

### 2.5 主要検定の弱さ(レビュー §3.6・§3.7 の再確認)と天井

- 交差しない交互作用は従属変数の単調変換で出たり消えたりし、二値・比率・天井のある尺度はその典型である [14][15][16][128][129][130]。logit の積項と確率の交互作用は符号まで変わりうる [131][132][133][134]
- **パイロットでは T1 の `id`・`interp` が両シードで 1.000** [run:pilot_ft_eval_p2_s0_n313] [run:pilot_ft_eval_p2_s1_n313]。本実験でも 10 シードの多くが 1.000 なら、logit の当てはめは分離(推定値が ±∞)に近づき、df = 2 の LRT が不安定になる。PLAN-034 は天井を外に置いた(ADR-114 決定9)
- 「平行 ⇒ 共有」は方法論の基準では強すぎる。解離から別過程を言うには非単調な関係(逆連合)が要り、1 本の単調曲線でも「1 つの潜在量と整合する」までしか言えない [17][18][90][135][138][139][140]
- **state-trace の図は、既知性 3 点だけでは単調性がほぼ自明に満たされる**ので、状態を動かす第 2 の操作が要る(レビュー案 C)[140][142][153][154][137]

### 2.6 シードの二峰と `ident` の形の変化(レビュー §3.2・§3.3 の再確認)

- `p2` s0 は T2 で rule 0.96〜0.99、s1 は 0.00〜0.18(other_error 0.83〜1.00)[run:pilot_ft_eval_p2_s0_n313] [run:pilot_ft_eval_p2_s1_n313]。分布内で同等でも分布外で割れることは FT で繰り返し報告されている [28][27][99][100][104][103]。LLM の LoRA での直接の報告は薄い [105][106][107][108]
- `ident` でも T2 の応答が文章から数だけに変わり、correct は 0.725〜0.812 [run:pilot_ft_eval_ident_s0_n313] [run:pilot_ft_eval_ident_s1_n313]。書式の特化は FT のごく初期に起こり、性能の低下は知識の喪失ではなく書式・課題の推定の変化だとする報告が複数ある [114][13][59][115][116][117]
- **シード単位の報告は ADR-114 決定7 で入った。**二峰の扱い(分類の規則と閾値)は凍結前の人間の判断として残っている

| **H2** 境界 | 付く場所が既知性・タスク型で変わる | — | — | 署名が既知性の水準で変わる | — | — | **T1 × T2 の交互作用が有意** |

- **E1 は H0-F を {H0-A, H1} から分ける。合成の署名は H0-A と H1 を分ける。主要検定は H2 を問う。**3 つの量がそれぞれ 1 つの切れ目を担う
- **非対称な推論(重要)**: T1c で t+4 が多ければ「演算子に付いた」の強い証拠になる。**t+2 が多くても H1 は退けられない** —— モデルが 3 項の和を一度に計算するなら(多項の加算には 2 項の加算に無い固有の限界があると報告されている [20]。2 項の繰り返しとして計算される保証は無い)、演算子の書き換えでも +2 しか出ないことがありうる。したがって **t+2 優勢の結論は「答えに付いた」と整合する、までである**
- `p2d`・`arb` の役割は「定数のずらしでなく和の関数である」ことの確認に**限定して**書き直す(§2.3)。H3(`p2` vs `p2d`。順1b)は変えない
- **現行の H0 / H1 / H2 との対応**: H0 → H0-F と H0-A に分ける(H0 の「最も強い版」は H0-A に入る)/ H1 → 合成の署名で操作的に定義し直す / H2 → 変えない。**H 番号の付け替えは config の `experiment.hypothesis`(= H2)を変えない**
- **これは旧 G2(代数的整合性。ADR-024 D-2 で廃止)の一部を戻す提案である。**ただし戻すのは単位元の言明・自己報告(メタ)ではなく、**行動の合成**だけである。D-2 の理由(主軸を既知性の勾配へ移した)とは衝突しない —— 合成の探りは既知性 × タスク型の装置の上に乗る

### 3.3 合成の探り(T1c)の骨子(仕様は実装の PLAN で凍結する)

- 形: 裸の式 `a+b+c=`(訓練の書式ブロックと同じ並び。PLAN-002 §4.8.1)
- 参照規則: **t・t+2・t+4 の 3 つ**(ADR-016 の参照規則ごとの 4 値ブロック)。offset = 2 なら 3 つは必ず割れる
- 被演算子の制約(案): すべて `[1, 99]`、**a+b+c が訓練の答えの範囲(`ans_in`)に入る**(大きさの外挿と混ざらないように)
- 既知性(案): 先頭の組 (a, b) が訓練の組 `K` に入る / 入らない(範囲内の未見)の 2 層
- 件数(案): セルあたり 80(T1 と同じ。ADR-114 決定3)
- 適格性: 素のモデルと `ident` で correct ≥ 0.70(既存の適格性フィルタと同じ線)。**届かなければ T1c は探索に落とす**(凍結前の素のモデルの確かめ = §5 の S4)
- 統計(案。凍結前に人間): シードを単位に d_s = rate_s(t+4) − rate_s(t+2) を求め、`p2` の 10 シードで平均 d の両側検定(符号反転の並べ替え検定)。報告は 4 値 × 3 参照規則をすべて
- 文章題版(T2c。3 つの量の文章題)は**探索**に置く案

### 3.4 確証的評価項目の族(主要検定は変えない)

| 量 | 何を分けるか | 位置づけ(案) | いまの状態 |
|---|---|---|---|
| 主要検定 T1 × T2 の `task:coverage` LRT(df = 2) | H2 か否か | **主要(変えない)** | ADR-112〜114。PLAN-034 は未実装のまま有効 |
| E1(T2 × 既知性 3 の `p2` − `ident`) | H0-F か否か | 門の外の確証(変えない) | ADR-112・113。TOST 境界と α の配分は凍結前に人間 |
| **合成の署名(T1c の d)** | H0-A か H1 か | **門の外の確証に 1 本足す**(E1 と同じ Holm の族) | 新規(D3・D5) |
| 順1b(`p2` vs `p2d`) | H3 | 変えない | ADR-053 決定3 |

### 3.5 天井への手当て: LoRA のスケールの掃引(レビュー案 C の具体化)

- 中身: 各アダプタの効き(LoRA の差分に掛ける係数 s)を s ∈ {0.25, 0.5, 0.75, 1.0}(案)で評価する。**訓練は増えない**。事前学習の重みと FT の重みの間を補間して評価する手法は、頑健な FT・重みの平均・モード連結性の研究で使われている [156][106][26][27][105]
- 得るもの: (i) 用量反応(病変の強さを連続に動かす)/ (ii) s < 1 では T1 が天井から下りるので、**既知性の勾配の情報が `id`・`interp` にも戻る** / (iii) x = T1 の rule、y = T2 の rule の **state-trace の図**(既知性 × スケールの点)で、1 本の単調曲線か順序の逆転かを見る [140][142][137][18][153][154]
- 位置づけ(案): **副次**(記述 + state-trace の単調性の検定)。主要検定は s = 1 のまま
- 費用: 評価の GPU 時間が水準の数だけ倍(推算)。パイロットの評価は 680 項目で約 134 秒 [run:pilot_ft_eval_p2_s0_n313]
- 注意: 1 本の曲線でも「1 つのシステム」とは言えない [138][139][17][135][150]。スケールの掃引は学習の途中の状態と同じではない(チェックポイントの掃引とは別物)

### 3.6 Phase 1 の LoRA の設定を 1 点に固定する

- いまの `04_EXPERIMENT_PLAN.md` は rank ∈ {1, 4, 16, 64} × 標的 3 通り × `train_size` {2000, 4000, 10000} を Phase 1 に置き、「グリッドを絞る」と書く。値は未決(ADR-043 決定10)
- 開いている問いが 2 つある: rank をまたいだ学習率の揃え方が文献で割れている(★rank と学習率)/ `num_steps` 固定では `train_size` の掃引が曝露回数を変えない(★`train_size`)
- **提案**: 本実験はパイロットの 1 点(rank 16・lr 1e-4・4 × 4・ADR-100。step 数は D7 の診断の後に人間)に固定する。用量反応は §3.5 のスケールの掃引で取る。rank・標的・`train_size` は本実験から外し、必要なら論文の後に探索で回す
- **得るもの**: 上の 2 件と LoRA グリッドの未決が消え、40 run の訓練の設定が 1 つになる

### 3.7 T2 の形の変化(レビュー案 F の具体化)
