### 5.2 費用(★推算。未実測)

パイロットの評価 1 本の記録: 合計 133.9 秒 = 重みの読み込み 95.9 秒 + 生成 30.6 秒(680 項目。1 項目 0.045 秒)[run:pilot_ft_eval_p2_s0_n313]。

## 7. 想定される交絡と罠

1. **凍結の前に `p2`・`p2d` の T1c・スケールの掃引を見る**(ADR-116 決定3)。D9 で止める。S4 の config は `ident` と素のモデルだけ
2. **2 段目の組が訓練域の外に出る**: 左から合成したとき (a+b+offset, c) が [1, 99]² の外だと、規則が弱まって t+2 に寄りうる。H1 の検出を不利にし、「答えに付いた」と取り違える。D2 (b) で防ぐ。(b, c) と 2 段目の被覆を記録するのは、後で同じ問いを確かめるため
3. **t+2 の優勢を「H1 を退けた」と読む**(非対称な推論)。`composition_table.py` は判定の文言を出さない
4. **素のモデルが `a+b+c=` に式を書き直して答える・途中の和で止まる**: `numeric` パーサの抽出規則(PLAN-001 §5.4.1)で parse_fail か other に入る。**S4 で見てからパーサを変えない**(変えるなら ADR を書き、T1・T2 の採点にも効くことを確かめる)
5. **s ≠ 1 の run が主解析に混ざる**: I8。順6b の ①・(d) で `aggregate.py` が見分けられなかった前例
6. **s = 0 が素のモデルと、s = 1 がアダプタそのものと一致しない**: S4 の配線確認で予測を突き合わせる(§8)。一致しなければ**配線を疑い、「ほぼ同じ」で済ませない**。生成のバッチの非決定性で揺れる可能性もある(未確認)ので、揺れが出たら件数と項目を報告する
7. **減算の内訳の優先順**: 重なる項目は先の候補に数えるので、順を変えると件数が変わる。D6 (a) はパイロットと同じ順に固定し、重なりの件数を別に出す
8. **pilot 側で測った適格性を主に持ち込む**: S4 の素のモデルの T1c は pilot の領域の項目で測る(§8)。主の項目とは組が違う。本実験の判定は凍結時に固定する規則で行う(ADR-116 決定3)
9. **T1c の先頭の組は T1 の `id` の組と重なりうる**(どちらも K から取る)。別のプロンプトなので文脈は持ち越さないが、項目表に重なりの件数を残す
