## 1. 目的(答える問い)

**「同じ条件のセルの中で、問題によって規則の付きやすさがどれだけ違うか」(`s2_item`、ロジット尺度の分散)を、手元の実測から見積もるとどのくらいか。**

- 出すのは**判断材料**(推定値・区間・推定が立ったかどうか)。**値の決定は人間**(ADR-119 決定3)
- 決まった値は `configs/power_sim.yaml` の `dgp.s2_item` に入れ、検出力分析の本実行(この機械・16 並列。ADR-119 決定1)へ進む

## 2. なぜ今これが推定できるのか(★F115 との違い)

- ★F115: 順6(素のモデル・1 シード)では 1 項目に 1 観測しかなく、`(1|item)` の profile 尤度が平らだった
- パイロット FT の `p2` は**同じ項目を 2 シードで解いている**。項目の当たり外れがシード間でどれだけ一致するかから、項目の分散が同定できる(シード間の分散は 2 水準なので弱い)

| run | 条件 | step |
|---|---|---|
| `pilot_ft_eval_p2_s0` / `pilot_ft_eval_p2_s1` | `p2` | 625 |

- **プールは `pool_id: pilot`。主張には使わない(ADR-106)。**ここでの使い方は「検出力分析の仮定値の材料」で、ADR-119 決定3 で承認された

## 4. 決めること(人間。次のセッションで表と推奨を付けて諮る)

- **D1 どの step を使うか**: 625 / 313 / 両方を別々に出す
- **D2 当てはめの式**: `is_rule ~ task * coverage + (1|seed) + (1|item)` を基本に、T2 の `(1|template)` を入れるか。タスク別に出すか、まとめて出すか
- **D3 `ans_out` の項目を含めるか**(主要検定の既知性 3 水準との対応)
- **D4 天井・床の扱い**: 規則率が 0 か 1 に寄ったセルでは分離が起き、項目の分散が発散するか 0 に張り付く。その場合の報告の形(推定が立たないことも結果として書く)
- **D5 何を出すか**: 点推定・profile の区間・縮退の有無・セルごとの規則率。**値の推奨は出すか**(ADR-119 決定2 の外し方はこの件に限る)

### 4.1 決まったこと(ADR-120。★推定を見る前に固定した。以後この節は打ち消し線でしか変えない)

**判断材料で分かった事実**(パイロットのプール。主張に使わない):
- `extrap_magnitude` の項目は `predictions/*.ans_out.jsonl`(80 行)にある。**`ans_out` は主要検定の既知性の 3 つ目の水準そのもの**(`frame.py` のラベル)。D3 の問いの前提はずれていた
- T1 の `id`・`interp` は両シード・両 step とも規則率 1.000(分離)。T2 の `id`・`interp` はシード 0 が 0.963〜0.988、シード 1 が 0.000〜0.025。**この 8 セルは `s2_item` に寄与しない**
- 手がかりは `extrap_magnitude` の T1(0.825 / 0.588〜0.600)・T2(0.750 / 0.175)だけ

| D | 決定 |
|---|---|
| D1 | **625 を主推定、313 は同じ手順で別に出して並べる**(混ぜない) |
| D2・D3 | **`extrap_magnitude` の T1・T2 だけ**(各 80 項目 × 2 シード)。主の式 `is_rule ~ task * seed + (1\|item) + (1\|template)`(`seed` は固定効果。`template` = `category`。`glmer`・binomial・Laplace・lme4 の既定の制御)。補助: T1 単独 `is_rule ~ seed + (1\|item)` / T2 単独 `is_rule ~ seed + (1\|item) + (1\|template)` / 主から `template` を抜いたもの |
| D4 | 分離したセルは件数つきで「寄与なし」/ 特異(`isSingular`)なら明記 / 項目の分散は profile 95% 区間(`confint(method = "profile")` の SD を 2 乗)/ profile が立たなければ「立たなかった」と書く / `glmer` を使わない照合として、セルごとにシード 0 × シード 1 の 2×2 の一致表 |
| D5 | **推奨値 = 主推定(625・主の式)の項目の分散の profile 95% 区間の上端。**区間が立たなければ推奨は出さない。**値を決めるのは人間** |

## 5. 手順(案)

1. D1〜D5 を人間に確認する
2. 抽出スクリプトと R の当てはめ(`lme4::glmer`。`power_sim_fit.R` と同じ環境)を `plans/PLAN-039-s2-item/` に置く
3. 結果を `results/s2_item_pilot/` に run_id とセットで書く
4. 人間が `s2_item` の値を決める → ADR → `configs/power_sim.yaml` に `s2_item` と `s2_tmpl`(0.5。ADR-119 決定4)を入れる → `--dry-run` → pytest → commit → 本実行

## 6. 罠

- **2 シードしかない。**シード間の分散と項目の分散の切り分けが弱い。区間が広いことを隠さない
- step 数が本番と違う可能性がある(Phase 1 の step 数は「数だけ」診断の後に決める。ADR-115 決定7)
- T2 は FT の後に応答の形が一律に変わった(`results/pilot_ft_t2_form/`)。T2 の項目の分散はその影響を受ける
- 推定を見てから値を決めるのは HARKing ではない(検出力分析は実験の前で、主要検定の結果を見ていない)。ただし**推定を見た後で取得元の規則を変えない**
